# 음성 파이프라인 실기 검증 매뉴얼

2026-07-23 음성 관련 변경(자가 트리거 차단, 안내 음성 복구, 긴급어 정리, 즉시 피드백,
거리 안내)을 Jetson 실기에서 확인하는 절차다.

환경 구축(venv, ROS2, CUDA, `.env`)은 `docs/jetson-setup.md`가 정본이다. 이 문서는
**이미 돌아가던 장비에서 이번 변경만 확인**하는 데 초점을 둔다.

변경 내용은 전부 **귀로 확인**할 수 있다. 그래서 이 문서는 "무엇을 하면 무엇이
들려야 하는가"로 구성했다.

---

## 0. 시작 전 3가지

| 확인 | 이유 |
| --- | --- |
| 물리 E-stop 버튼 위치를 손이 닿는 곳에 둔다 | 소프트웨어 E-stop 중앙 래치는 아직 `[GAP]`이다 |
| **1~3단계는 바퀴를 띄우거나 모터를 끄고 한다** | 소리만 확인하는 단계라 로봇이 움직일 이유가 없다 |
| 관리자 앱을 켜 둔다 | E-stop이 걸리면 앱 reset 외에는 해제 수단이 없다 |

> ⚠️ 긴급어가 잘못 걸리면 로봇이 멈추고, 해제하려면 관리자 앱이 필요하다.
> 이번 변경의 목적 중 하나가 그 오작동을 없애는 것이지만, 검증 전에는 확인되지 않은
> 상태로 취급한다.

colcon build --packages-select vica_mission_manager

### 왜 같이 올려야 하나

이번에 `/vica/tts_state`라는 토픽이 새로 생겼고, TTS 노드가 듣던 토픽이 바뀌었다.

| 조합 | 결과 |
| --- | --- |
| 둘 다 새 버전 | 정상 |
| TTS만 새 버전 | LLM 응답이 안 들린다 |

## 2. 소리만 확인 (로봇 없음)

터미널 3개를 쓴다. 모든 터미널에서 먼저:

```bash
source /opt/ros/humble/setup.bash
source ~/dev/vica-voice-llm/ros2_ws/install/setup.bash
cd ~/dev/vica-voice-llm
```

**터미널 1 — 음성 노드**

```bash
ros2 launch launch/vica_voice.launch.py
```

LLM · TTS · 긴급어 감시 세 노드가 뜬다. 로그에 다음이 보여야 한다.

```
VICA TTS node 시작 (구독: /vica/tts_request | 발행: /vica/tts_state)
VICA 긴급어 상시 감시 시작 (발행: /vica/emergency, 구독: /vica/tts_state)
```

`/vica/tts_state`가 두 줄에 다 나와야 한다. 없으면 옛 버전이다.

**터미널 2 — 감시용**

```bash
ros2 topic echo /vica/emergency      # 긴급어가 잡힐 때만 출력
```

**터미널 3 — 조작용**

아래 시험들을 여기서 실행한다.

---

### 시험 2-1. 로봇이 자기 목소리에 반응하지 않는가 ★ 가장 중요

```bash
ros2 topic pub -1 /vica/tts_request std_msgs/String \
  "{data: 'narration:지금 이동 중입니다. 먼저 현재 안내를 취소해 주세요.'}"
```

| 확인 | 기대 |
| --- | --- |
| 소리 | 두 문장이 **끊어서** 재생된다 |
| 터미널 2 | **아무것도 출력되지 않는다** |

터미널 2에 뭔가 뜨면 자가 트리거가 살아 있는 것이다. 즉시 중단하고 기록한다.

**스피커 볼륨을 최대로 올리고 한 번 더** 한다. 잔향이 큰 환경일수록 잘 드러난다.

이어서 예전에 문제였던 목적지 이름도 확인한다.

```bash
ros2 topic pub -1 /vica/tts_request std_msgs/String \
  "{data: 'narration:행정대학건물 1층 행정지원실 앞에 도착했습니다.'}"
```

역시 터미널 2에 아무것도 나오지 않아야 한다.

---

### 시험 2-2. 말하는 중 신호가 켜지고 꺼지는가

터미널 2를 잠시 바꿔서:

```bash
ros2 topic echo /vica/tts_state
```

긴 문장을 재생시키면 `true` → `false`가 **문장 수만큼 반복**되어야 한다.
계속 `true`로 남아 있으면 안 된다.

```bash
ros2 topic pub -1 /vica/tts_request std_msgs/String \
  "{data: 'narration:첫 번째 문장입니다. 두 번째 문장입니다. 세 번째 문장입니다.'}"
```

---

### 시험 2-3. 급한 말이 하던 말을 끊는가

긴 문장을 재생시키고, **재생 중에** 다음을 실행한다.

```bash
ros2 topic pub -1 /vica/tts_request std_msgs/String \
  "{data: 'emergency:안전을 위해 멈추겠습니다.'}"
```

기대: 하던 말이 즉시 끊기고 긴급 문장이 나온다. 끊긴 말은 이어지지 않는다.

---

### 시험 2-4. 사람 목소리에는 여전히 반응하는가 ★ 안전 확인

**마이크에 직접** "멈춰"라고 말한다. (로봇이 말하고 있지 않을 때)

기대: 터미널 2에 `keyword: 멈춰`가 뜬다.

> 이 시험이 실패하면 mute가 과하게 걸린 것이다. 안전 기능이 죽은 상태이므로
> **다음 단계로 진행하지 않는다.**

이어서 **로봇이 말한 직후 1초 안에** "멈춰"라고 해 본다. 감시가 다시 열리기까지
약 2.4초 걸리므로 이때는 안 잡힐 수 있다. 이건 설계된 동작이고, 그 값이 실제
사용에서 너무 긴지 판단해 기록한다.

---

### 시험 2-5. 오탐이 사라졌는가

마이크에 대고 다음을 말한다. **전부 터미널 2에 아무것도 뜨면 안 된다.**

- "천천히 가주세요"
- "잠깐만요"
- "행정지원실로 가줘"
- "감정지수가 뭐야"

## 3. 대화 확인 (LLM 포함)

**터미널 3**에서 STT 노드를 띄운다.

```bash
.venv/bin/python -m src.ros_stt_node
```

엔터를 눌러 녹음하고, 말한 뒤 다시 엔터.

| 시험 | 말할 것 | 기대 |
| --- | --- | --- |
| 3-1 즉시 응답 | "식당으로 가줘" | 곧바로 **"네."** → 잠시 후 확인 질문 |
| 3-2 인식 실패 | 엔터만 두 번 (무음 녹음) | **"잘 듣지 못했습니다. 다시 말씀해 주세요."** |
| 3-3 감속 요청 | "천천히 가주세요" | LLM이 일반 대화로 답한다. "멈추겠습니다"가 **나오면 안 된다** |
| 3-4 STT 정확도 | "식당으로 가줘" | 로그의 인식 결과가 "직당" 같이 틀리지 않는다 |

3-1의 "네."가 거슬리는지 여기서 판단한다. 거슬리면 `src/replies.py`의
`ACK_LISTENING` 한 줄만 고치면 된다(빈 문자열로 두면 나가지 않는다).

3-4는 STT 모델을 `medium`으로 올린 효과 확인이다. `.env`에 이미
`VICA_STT_MODEL=medium`이 있다면 동작은 전과 같고, 코드 기본값이 실기 설정과
일치하게 된 것뿐이다.

## 4. 주행 포함 확인

여기서부터 로봇이 실제로 움직인다. **물리 E-stop을 손에 잡고 시작한다.**

```bash
# 안전 계층
ros2 launch mdrobot_can_control safety_bringup.launch.py

# Nav2
ros2 launch vica_nav2 nav2_map_test.launch.py map:=<지도 yaml 절대경로>

# Mission Manager + 긴급어 브리지
ros2 launch vica_mission_manager mission_manager.launch.py \
  destinations_yaml:=<vica-voice-llm/config/destinations.yaml 절대경로> \
  map_yaml:=<지도 yaml 절대경로>
```

> ⚠️ `mission_manager.launch.py`의 기본 경로는 `/home/ji_w/tony/...`로 박혀 있다.
> 실기 계정이 다르면 **반드시 두 인자를 직접 넘긴다.** 안 그러면 목적지를 못 읽는다.

| 시험 | 할 것 | 기대 |
| --- | --- | --- |
| 4-1 안내 시작 | 목적지 요청 → 확인 | **"○○(으)로 안내를 시작합니다"** 가 들린다 |
| 4-2 거리 안내 | 10m 이상 떨어진 목적지 | 남은 10m·3m 지점에서 한 번씩 안내 |
| 4-3 도착 | 끝까지 주행 | **"○○ 앞에 도착했습니다"** 가 들린다 |
| 4-4 중복 요청 | 주행 중 다른 목적지 요청 | "먼저 현재 안내를 **취소해** 주세요" (멈춰 ✗) |
| 4-5 긴급 정지 | 주행 중 "멈춰" | 로봇 정지 + "안전을 위해 멈추겠습니다" |

**4-1과 4-3은 이번 작업의 핵심이다.** 전에는 이 말들이 아예 안 나왔다.

4-2에서 거리가 실제 감각과 맞는지 본다. Nav2의 남은 거리는 직선이 아니라 경로
기준이라 체감보다 길게 나올 수 있다. 지점 값은 `mission_logic.py`의
`DISTANCE_MILESTONES_M`에서 조정한다.

4-5 이후 로봇은 래치 상태로 남는다. 관리자 앱으로 reset한다.

## 5. 하루 뒤 확인 (선택)

대화 맥락 초기화는 3분 간격이 필요해 마지막에 따로 본다.

1. "식당으로 가줘" → 확인 질문까지 듣고 답하지 않는다
2. **3분 이상 기다린다**
3. "거기로 가줘"

기대: 앞의 식당을 기억하지 않고 되묻는다. LLM 노드 로그에
`대화가 끊겨 이전 맥락을 비웠다`가 찍힌다.

## 6. 조정 가능한 값

실기에서 만져야 할 가능성이 높은 순서다.

| 값 | 위치 | 기본 | 언제 바꾸나 |
| --- | --- | --- | --- |
| 재생 후 대기 | `src/ros_tts_node.py` `TAIL_SEC` | 0.4초 | 시험 2-1에서 자가 트리거가 나면 늘린다 |
| 문장 최대 길이 | `src/tts_text.py` `MAX_CHUNK_CHARS` | 40자 | 시험 2-4에서 감시 공백이 길게 느껴지면 줄인다 |
| 즉시 응답 문구 | `src/replies.py` `ACK_LISTENING` | "네." | 거슬리면 바꾸거나 비운다 |
| 거리 안내 지점 | `mission_logic.py` `DISTANCE_MILESTONES_M` | 10m, 3m | 실제 거리 감각과 맞춘다 |
| 대화 초기화 시간 | `src/history.py` `DEFAULT_IDLE_RESET_SEC` | 180초 | 사용 패턴에 맞춘다 |
| mute 안전장치 | `src/emergency_monitor.py` `max_mute_sec` | 8초 | 긴 안내가 잘리면 늘린다 |

값을 바꾸면 자동 검사를 다시 돌린다. 특히 **문구를 바꿨을 때는 반드시** 돌린다 —
긴급어가 섞이면 검사가 막아 준다.

## 7. 문제가 생기면

| 증상 | 먼저 볼 곳 |
| --- | --- |
| 아무 소리도 안 난다 | `ros2 topic echo /vica/tts_request` 로 요청이 오는지 |
| 요청은 오는데 소리가 없다 | TTS 노드 로그의 `재생 실패` (오디오 장치) |
| 로봇이 자기 말에 멈춘다 | 두 저장소가 모두 새 버전인지, `/vica/tts_state`가 켜지는지 |
| 사람 "멈춰"에 반응이 없다 | `/vica/tts_state`가 `true`로 눌러붙어 있는지 |
| 안내 멘트가 안 들린다 | Mission Manager를 `colcon build` 했는지 |
| 말이 밀려서 늦게 나온다 | TTS 노드 로그의 `발화 대기` 줄 수 |

되돌리려면 두 저장소 모두 이전 커밋으로 돌린다. **한쪽만 되돌리면 더 나빠진다.**
