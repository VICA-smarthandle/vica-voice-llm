# 사람 접근 음성 흐름 — 확정 설계 (2026-08-25)

사용자(음성 담당) 결정. 인수 문서(`devlog/2026-08-25-사람접근-완주와-음성인수인계.md`,
루트 저장소 `docs/person-approach-design` 브랜치)의 후속이며, 구현 상태는 맨 아래.

## 확정 흐름

```
사람 앞 1.1 m 정지
→ [녹음] 접근 질문: "안녕하세요? 저는 시각장애인 안내로봇 비카입니다!
   저와 함께 목적지까지 동행해보시는건 어떠세요? 안내를 받으시겠어요?"
   (assets/approach_question.wav · 10.6 s)
→ 답 대기 — 8초는 **재생 종료 시점부터** 센다 (TTS 재생완료 이벤트 필요)
   · 이 단계의 답은 방향을 따지지 않는다 (barge-in 은 방향 증거가 없어 잠듦
     — 재생 종료 후 재청취 창이 방향 무관으로 받는다. 재생 중 답은 유실 수용)
→ affirm
→ Say "네, 잠시만 기다려주세요. 로봇이 회전하니 주의하세요" + 180도 회전 시작
   (시각장애인에게 예고 없는 움직임 금지 — 회전 예고가 안전 멘트다)
→ 회전 완료
→ Say "회전이 완료되었습니다"
→ [녹음] 온보딩: "안녕하세요? 반갑습니다! 저를 부르시려면 '비카야'라고
   불러주시면 됩니다! 자, 이제 어디로 가고싶으신가요?"
   (assets/approach_onboarding.wav · 9.6 s)
→ 재청취 창 — **이 시점부터 DOA(방향) 판단 활성**
   (회전으로 사용자가 핸들 방향에 정렬됨 = 장착 보정 부채꼴이 유효해짐.
    별도 상태 스위치 불필요 — 기존 방향 관문이 자연히 맞아떨어진다)

deny → Say "알겠습니다. 이만 물러납니다" → 복귀(RETURNING)
```

## 구현 상태

| 조각 | 위치 | 상태 |
| --- | --- | --- |
| affirm/deny 발행 (0초 단축 + LLM 폴백) | voice `5a4ddea` | ✅ 책상 시험 273 통과 |
| 접근 질문·온보딩 녹음 | voice `00ffd9c` | ✅ 생성됨 (재생 배선은 문장 캐시에서) |
| TTS 문장 캐시 (고정 멘트 → 녹음 재생) | voice | ⬜ |
| TTS 재생완료 이벤트 (8초 기점) | voice + ros2 구독 | ⬜ **필수 승격** — 질문이 10.6 s 라 생성 시점 기산이면 시한 소진 |
| 회전 예고·완료 멘트 + **회전 완료 훅** (완료 후 온보딩·재청취) | ros2 mission | ⬜ |
| deny "이만 물러납니다" 멘트 | ros2 mission | ⬜ |
| 실기 검증 (인수 문서 2.4의 3종 + 회전 후 barge-in) | 로봇 | ⬜ 마이크 장착 후 |
