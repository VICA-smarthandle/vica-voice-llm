# 마이크 현장 점검기 사용법

시연장에 도착하면 한 번 돌려 "이 장소에서 비카가 제대로 듣는가"를 관리자 앱으로 확인한다. 기본은 확인만 한다.
값을 고치고 싶으면 화면에서 바꿔 다시 채점하고, 원하면 `.env` 에 저장한다(백업·되돌리기 있음).
설계: `docs/superpowers/specs/2026-10-12-mic-venue-check-design.md`

## 시작

1. 로봇은 멈춰 있어야 한다(주행 중 금지). 앱을 로봇과 같은 와이파이에 붙인다.
2. 앱에서 연다 — 대시보드의 '주행 설정' 칸(음성 노드를 끄고, 로봇 정지 상태) 또는 모드 선택 화면(주행 꺼짐) → '마이크 점검'.
   음성 노드가 켜져 있거나 로봇이 움직이는 중이면 시작되지 않는다.
3. 점검기는 로봇의 모드 노드가 `vica-miccheck.service`(포트 8770)로 띄운다. 터미널에서 직접 실행하면
   `VICA_MIC_CHECK_LAUNCHER=mode` 표지가 없어 거절된다(`--demo`·`--restore` 제외).

1단계 준비(모델 올리기, 칩에 `.env` 값 쓰기)는 점검기가 스스로 한다. 모델을 올리는 1~2분 동안 앱에 "준비하는 중"이 보인다.
음성 노드와 같은 장소 귀띔은 모드 노드가 지도 목적지 파일(`~/vica_data/destinations/<지도>/destinations.yaml`)이 있으면 `--destinations` 로 자동으로 붙인다.

## 순서 (약 10~12분, 손잡이 자리에 서서 — 7·8단계는 자리를 옮긴다)

| 단계 | 할 일 |
|---|---|
| 2 조용히 | "녹음 시작"을 누르고 15초 말하지 않는다 |
| 3 호출 | 앞의 3번은 "비카야" 한 박자 쉬고 "화장실로 가자", 뒤의 2번은 "비카야화장실로가자" 쉬지 않고 이어서 (녹음 6초) |
| 4 짧은 답 | "그래" 2번, "아니" 2번 |
| 5 멈춰 | "멈춰" 5번(진짜 비상정지는 걸리지 않는다) |
| 6 로봇 혼자 말하기 | "로봇 말하기 시작"을 누르고 30초 조용히 |
| 7 먼 대답 | 로봇 앞 1~1.5 m 에서 "그래" 1번, "아니" 1번 — 접근 질문('안내를 받으시겠어요?') 대답처럼 (녹음 4초) |
| 8 옆사람 | 사용자는 조용히, 옆사람이 1~3 m 에서 평소 목소리로 잡담 3번 (녹음 6초) |
| 9 결과표 | 읽고, 필요하면 값을 고친다 |

7·8단계(2026-10-21 추가)는 "옆사람 말은 막히고 사용자 말은 들리는가"를 본다.
- 먼 대답은 음성 노드처럼 호출을 끄고 **접근 대답 최소**(`VICA_APPROACH_MIN_RMS`, 줄이 없으면 수음 최소)로 받아 채점한다.
- 옆사람 잡담은 질문 창(수음 최소)과 접근 대답 창(접근 대답 최소)에 따로 흘린다. 받아쓰기까지 가면 샌 것이다:
  질문 창에서 새면 불합격, 접근 창에서만 새면 주의.
- 옆사람 줄에는 옆사람 최대 소리, 4단계 사용자 최소 소리와의 dB 차, 둘을 가르는 수음 최소(기하 평균),
  7단계 먼 대답과의 dB 차가 함께 나온다.

단계는 진행 칸의 "다시"로 따로 다시 할 수 있다.

## 결과 읽기

- **사용 가능**: 그대로 쓴다.
- **사용 가능 · 확인 필요**: 주의 줄의 안내를 읽는다(아슬아슬한 곳).
- **다시 녹음 필요**: AGC·에코·문턱을 바꿔 그 단계 녹음이 무효다. 해당 단계를 다시 한다.
- **고친 뒤 다시**: 불합격 줄의 할 일을 하고 그 단계를 다시 한다. 로봇이 자기 말에 반응했으면 먼저 스피커 볼륨을 낮춘다.

결과표는 남긴 녹음을 음성 노드와 같은 귀로 다시 채점한 것이다. 위쪽 "판정" 칸은 실시간으로 바로 보이는 것이고, 드물게 다를 수 있다.

"이어서 부르기" 줄은 참고용이라 '주의'까지만 나온다. 지금 귀는 "비카야"를 확인한 뒤에 듣기 창을 열어서,
쉬지 않고 말하면 목적지 머리("화장실")를 놓친다(10-13 실측 3번 중 3번). 값으로 고칠 수 있는 문제가 아니므로
시연 때는 "비카야" 뒤 "네?"를 듣고 말한다. 호출 줄은 받아쓴 말에 "화장실"이 있어야 합격이다.

## 값 고치기

- 막대·단추로 바꾸면 앱 화면의 기준선이 바로 움직인다. 그 자리에서 말해 보며 본다.
- **다시 채점**: 남긴 녹음을 새 값으로 다시 본다(말할 필요 없음). AGC·에코를 바꿨으면 해당 단계를 다시 녹음해야 한다.
- 수음 최소 막대는 0.005~0.040, 짧은 답 최소는 0.010~0.050 이다(2026-10-22 복도 ×4 에서 가를 수음 최소 ≈0.032 —
  넓혔다). 저장 검사는 '짧은 답 최소 ≥ 수음 최소'(같아도 됨)다 — 10-06 설계 초기값 1.5배를 1.0배로 내렸다.
- 값은 10개다. 2026-10-21 에 셋이 늘었다:

  | 값 | `.env` 키 | 고치는 법 | 바꾸면 |
  |---|---|---|---|
  | AGC 최대 증폭 | `VICA_MIC_AGC_MAX_GAIN` | ×2 · ×4 · ×8 · ×31.6(공장값) 단추 | 칩이 소리를 바꾼다 — 2~8단계 다시 녹음 |
  | 접근 대답 최소 | `VICA_APPROACH_MIN_RMS` | 막대 0.002~0.030 | 다시 채점만 |
  | 말소리 대역 최소 | `VICA_LISTEN_BAND_MIN` | 막대 0.001~0.008 | 다시 채점만 |

  최대 증폭을 ×4 → ×2 로 내리면 소리가 약 −6 dB(절반)가 된다. 접근 대답 최소(0.006 → 약 0.003)·대역 최소(0.004 → 약
  0.002)를 함께 낮춰야 할 수 있다 — 7·8단계 줄로 확인한다. 재채점은 음성 노드처럼 대역 관문을 켠 귀로 한다(그 전에는 꺼져 있었다).
- 최대 증폭 줄이 없으면 점검기는 칩에 공장값 ×31.6 을 직접 쓴다(음성 노드는 줄이 없으면 칩에 쓰지 않는다). 저장하지 않은 ×2 시험이
  끝낸 뒤 칩에 남아 음성 노드로 넘어가지 않게 하려는 것이다.
- **저장…**: `.env` 에 쓸 줄을 먼저 보여 주고, "확인하고 저장"을 눌러야 쓴다. 쓰기 전에 `~/vica_data/mic_checks/env_backups/` 에 백업한다.
  바꾼 줄 끝에 `# MM-DD <장소> 점검에서 바꿈 (전 <옛 값>)` 이 남는다. **음성 노드를 다시 켜야 적용된다.**
- **원래대로**: 마이크 값 10개만 가장 최근 백업(마지막 저장 직전)의 값으로 되돌린다. 지도·목적지 같은 다른 줄은 그대로다(백업에 없던 마이크 줄은 점검기가 쓴 줄 — 끝에 "점검에서 바꿈"·"원래대로" 표시 — 만 지워 기본값으로 돌아간다. 손으로 넣은 줄은 그대로 둔다). 되돌리기 전 지금 `.env` 는 `.env.<시각>.before-restore` 로 남긴다. 비상시 터미널에서는 `.venv/bin/python -m tools.mic_venue_check --restore` (`[y/N]` 로 한 번 묻는다).

## 끝낸 뒤

1. 앱의 "끝내기". 칩은 `.env` 값으로 되돌아간다.
2. 음성 노드를 켜고 시작 로그의 `수음 최소 … · 짧은 답 최소 … · 접근 대답 최소 … · 말소리 대역 최소 …`, `AGC 목표 레벨 설정`,
   `AGC 최대 증폭 한도 설정`, `에코 억제 설정` 값을 확인한다.
3. 시연 대화를 한 번 해 본다: "비카야" → "네?"를 듣고 목적지 → 확인 질문에 "그래".
4. 저장했다면 시연이 끝난 뒤 되돌리기를 잊지 않는다.

## 기록

`~/vica_data/mic_checks/<날짜-시각>_<장소>/` — `result.json`(값·측정·판정·재채점·저장 이력), 녹음 wav 와 조각별
칩 사람 말 표시(`*.vad.json`), `events.log`. 여러 번 돌린 결과로 `src/mic_check_rules.py` 위쪽의 기준 숫자를 다듬는다.
"지난 점검" 로봇 목소리 크기 비교는 이 폴더의 가장 최근 기록을 쓴다 — 시연 전에 연구실에서 한 번 돌려 둔다.

## 화면 개발용 `--demo`

`.venv/bin/python -m tools.mic_venue_check --demo --port 8771` — 마이크·모델 없이 가짜 소리로 움직이고, 앱을 이 주소로 붙여 화면을 본다.
미리 보기 기록은 `~/vica_data/mic_checks/demo/<날짜-시각>_<이름>/` 에 남고, 저장·되돌리기도 그 폴더의 `demo.env` 에만 쓴다.
`demo/` 폴더는 가짜 로봇 소리 크기가 "지난 점검" 기준으로 잡히지 않도록 따로 둔 것이다. 실제 `.env` 는 건드리지 않는다.

## 문제 해결

| 증상 | 할 일 |
|---|---|
| 앱에서 '마이크 점검'이 시작되지 않는다 | 음성 노드가 켜져 있거나 로봇이 움직이는 중이다. 앱에서 음성 노드를 끄고 정지한 뒤 다시 누른다 |
| "reSpeaker 상태 레지스터를 읽을 수 없습니다" | USB 를 다시 꽂고 udev 규칙 확인 |
| 상태 줄 "칩 쓰기 문제" | 칩 값이 `.env` 와 다를 수 있다. 앱 위쪽 빨간 글을 보고 끝내기 뒤 다시 시작한다. 이 상태에서는 녹음·6단계가 시작되지 않는다 |
| 앱이 못 붙는다 | 같은 와이파이인지, 8770 을 다른 프로그램이 쓰는지(`vica-miccheck.service` 가 곧 끝나면 앱이 "점검기가 끝났습니다"를 띄운다) |
| "VICA_EMERGENCY_SINGLE_FRAME 이 off" | `.env` 의 그 줄을 지우거나 숫자로 바꾼다 |
