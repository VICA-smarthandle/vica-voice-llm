# 귀 받아쓰기를 Qwen3-ASR 로 바꾸기 설계 (stt-qwen-asr)

작성 2026-10-15 · 저장소 `vica-voice-llm` · 브랜치 `feat/stt-qwen-asr`(작업 폴더 `~/wt-stt-qwen`, 기준 `after_feedback_waiting` e0bfc13)
상태: 10-15 사용자 결정 반영(주행 막기 안 함·보강은 감싸개 안에서만·정답 달기 함)

## 0. 배경

### 0.1 왜 바꾸나 — 개인정보

시연 심사에서 "음성 수집 동의를 받았나", "정보를 국외로 보내나"(개인정보 보호법)를 물으면 지금 구성은 답이 궁하다.
⑫ 는 사용자의 **목소리 자체**를 OpenAI Realtime(국외 서버)으로 보낸다. 사용자 판단(10-15):

- 가장 안전한 것은 **소리도 글자도 로봇 밖으로 나가지 않는 구성**(로컬 STT + 로컬 LLM)이다.
- 최악이라도 **글자만** 클라우드로 보내는 편이 목소리를 보내는 것보다 낫다.
- Realtime 도입(09-20) 전에는 STT + 로컬 LLM 으로 계속 돌렸으므로 되돌아갈 길이 있다.

그래서 순서는 ① 귀의 whisper 를 Qwen 으로(이 문서 1·3단계) ② Realtime 을 글자 경로로 대체(2단계)다. 셋 다 시연(≈10-27) 전에 시험한다.

### 0.3 문지기 — 오늘의 핵심 발견

Qwen3-ASR 은 말소리가 없으면 `language None` 을 내도록 학습됐다(기술 보고서 2.2 절). 그런데 `language="ko"` 로 고정하면
transcribe.cpp 가 답의 머리를 `language Korean<asr_text>` 로 미리 채워(src/arch/qwen3_asr/model.cpp:593-605) 모델이 "말 없음"을
말할 수 없다. 그래서 침묵에 '네.'·'응.'·'이미' 가 나왔다. 반대로 언어를 비워 두면 침묵은 7/7 빈칸이지만, 짧은 한국어를
중국어·태국어로 착각한다('응'→'嗯', '네'→'那'; 정답 216 중 1.7B 137).

그래서 둘을 잇는다.

1. 1차: 언어를 비우고 받아쓴다.
2. 결과 언어가 없으면(`language None`) → 빈칸(말 없음).
3. 결과 언어가 한국어면 → 그 글자를 쓴다(2차와 글자 같음 307/310).
4. 그 밖의 언어면 → 2차로 한국어 고정 받아쓰기를 한 번 더 한다(460개 중 약 25 %).

## 2. 범위

하는 것:

- 귀(`vica_wakeword`)의 whisper 두 벌(대화 turbo, 긴급 확인 small)을 역할별로 Qwen 1.7B 로 바꿀 수 있게 한다(기본값 whisper).
- 문지기, 예외 흡수, 시간 상한, 예열, 실패 시 노드 종료.
- 숫자 한글 표기 정리(목적지 찾기·에코 비교용).
- 2단계: 이미 있는 글자 모드(`VICA_INTENT_INPUT=text` + 로컬 LLM)를 시연 구성으로 시험한다.

하지 않는 것:

- Realtime 코드 삭제(`.env` 로 끄고 켤 수 있게 그대로 둔다).
- 귀 받아쓰기 일꾼 스레드 분리(10-10 사용자 거절, 시연 전 재제안 금지).
- 귀띔(장소 이름·대답 후보)을 Qwen 에 주기 — 침묵에 목록 자체를 적는다(오늘 실측, 공식 이슈 #106·#140·#186).
- TensorRT·미세조정·스트리밍 — 시연 뒤.
- `.venv` 에 설치 — `.venv` 는 운영 ⑫ 와 공유된다.

## 3. 지금 구조 — 바꿀 곳

- 귀가 whisper 를 올리는 곳은 `WakewordMonitor._load_real()`(src/wakeword_monitor.py:1344-1415) 한 함수다. 받아쓰기 함수 셋을 끼운다.
  - `_transcribe`(긴급 확인): small, beam 5, 필터 없음.
  - `_transcribe_listen`(자유 창): turbo + 장소 귀띔 + `accept_segments`.
  - `_transcribe_confirm`(질문 창): turbo + `CONFIRM_HINT` + `accept_segments`.
- 나머지 감시기 코드는 "int16 소리 → 글자" 함수만 부른다(411·420·421 주입 인자). 호출부(1130 긴급, 1302 청취)는 손대지 않는다.
- 감시 루프는 스레드 하나라 STT 동안 '비카야'·'멈춰' 처리가 밀린다. 운영 로그 2,659창의 대화 STT 는 중앙 1.59 s · p90 2.13 s 였다.
- 감시 루프·STT 호출·`_load_real` 에 예외 처리가 없다. 예외 하나면 감시 스레드만 죽고 노드는 살아 보인다(1417-1475, ros_wakeword_node.py:246).
- 위험한 연결 두 가지:
  - 긴급 관문 오발동 때 질문 답을 기다리는 중이면 그 전사를 사용자 답으로 넘긴다(1159-1173, `followup_answer`).
  - 확인 질문 중 첫 낱말이 긍정어('네'·'응'·'어'·'맞아' 등, handle_mode.py:85)면 LLM 없이 곧바로 출발한다(langchain_intent_parser.py:640-689).

## 4. 설계

### 4.1 역할별 엔진 스위치

새 `.env` 키만 쓴다. 기존 `VICA_STT_MODEL`·`VICA_VERIFY_STT_MODEL` 은 다시 쓰지 않는다 — 같은 `.env` 를 읽는 옛 코드가 gguf 경로를 whisper 로 올리려다 죽는다.

| 키 | 값 | 기본 |
|---|---|---|
| `VICA_STT_ENGINE` | `whisper` \| `qwen` (자유·질문 창) | `whisper` |
| `VICA_VERIFY_STT_ENGINE` | `whisper` \| `qwen` (긴급 확인) | `whisper` |
| `VICA_QWEN_MODEL` | gguf 경로 | 없음(qwen 인데 비면 실패) |
| `VICA_TRANSCRIBE_LIB` | libtranscribe.so 경로 | 없음 |
| `VICA_TRANSCRIBE_PY` | 바인딩 파이썬 경로(`bindings/python/src`) | 없음 |
| `VICA_QWEN_THREADS` | CPU 스레드 수 | 4(측정 후 확정, 라이브러리 기본은 8) |

- 경로는 코드에 박지 않는다(AGENTS.md:34 개인 경로 금지).
- 두 역할이 모두 qwen 이면 Model 하나를 같이 쓴다. 감시 루프가 스레드 하나라 동시에 부를 일이 없다.
- whisper 를 쓰는 역할이 하나라도 있을 때만 `from . import stt`(CUDA libctranslate2 선적재)와 faster_whisper 를 부른다.
- 시작 로그에 엔진과 모델을 적는다(ros_wakeword_node.py:212-216). 예: `긴급 확인 STT qwen(Qwen3-ASR-1.7B-Q8_0) · 대화 STT qwen(…)`.
- `ear_stt_model_names()`(205)는 시험이 반환 모양을 고정하므로 두고, 엔진을 돌려주는 함수를 따로 둔다.

### 4.2 Qwen 감싸개 — 새 파일 `src/stt_qwen.py`

- 바인딩은 쓸 때만 부른다(지연 import). 그래야 transcribe.cpp 가 없는 PC 에서도 시험이 돈다.
- 적재 직후 1 s 무음으로 예열한다(결과는 버린다). 마이크 스트림을 열기 전에 끝낸다.
- 입력: int16 → float32 1차원(바인딩은 int16·빈 배열을 거부한다).
- 역할별 받아쓰기:
  - 자유·질문 창: 0.3 절 문지기.
  - 긴급 확인: 한국어 고정 한 번만(빠르게). 문지기는 4.4 절의 넘기기 직전에만 쓴다.
- 예외: transcribe.cpp 의 모든 오류를 잡는다. 반복·잘림(`OutputRepetition`·`OutputTruncated`)은 빈칸으로, 그 밖은 빈칸 + 오류 로그.
  연속 오류가 몇 번 넘으면 4.5 절의 '귀 고장' 으로 올린다.
- 시간 상한: 입력은 청취 상한(15 s)까지만, 세션 문맥(n_ctx) 상한을 둔다. 실행별 취소(cancel)를 시한으로 건다.
- 문장부호만 남으면('.') 빈칸.
- 기록: 1차 언어, 2차 실행 여부, 걸린 시간을 기존 '계측: … STT …s' 줄 뒤에 덧붙인다(`scripts/voice_latency_report.py` 정규식 호환 유지).

### 4.3 지키는 것·끄는 것

| 항목 | Qwen 에서 | 이유 |
|---|---|---|
| `accept_segments`(no_speech_prob·avg_logprob) | 쓰지 않음 | Qwen 결과에는 그 값이 없어 아무것도 못 거른다(stt_guard.py:121). 문지기가 대신한다 |
| `is_hallucination`(유튜브 말투 목록) | 그대로 | 해가 없다. Qwen 유령은 목록으로 못 막는다('네'는 넣을 수 없음) |
| 장소 귀띔·`CONFIRM_HINT` | 주지 않음 | 침묵에 목록 자체를 적는다 |
| 숫자 한글 표기('사백칠호') | 목적지 찾기 앞에서 숫자로 정리 | 지금 `match_destination` 은 '사백칠호' 를 '407' 과 못 맞춘다(실측). LLM 에는 원문을 그대로 준다 |
| 에코 걷어내기(`strip_robot_echo`) | 비교할 때만 숫자 정리를 같이 | '407로'↔'사백칠로' 차이로 못 걷어낸다 |
| 앞머리 '네' | **1단계는 떼지 않는다**(권고) | 아래 |

앞머리 '네'에 대한 권고:

- 원인은 로봇의 '네?'(호출 응답)가 자유 창 머리에 섞여 들어가는 것으로 본다(미확인).
- 현장 182개에서 '네'로 시작한 긴 문장은 turbo 4 · **1.7B 5** · 0.6B 13 이었다. 1.7B 에서는 지금 whisper 와 거의 같다.
- 무조건 떼면 진짜 대답 '네'를 버릴 수 있다. 그래서 1단계에서는 떼지 않고, '네?' 재생 중에 시작한 창을 기록만 한다.
  시험에서 문제가 보이면 그때 "'네?' 재생이 끝나기 전 소리는 버린다"(시각 기준)를 넣는다.

### 4.4 긴급 확인을 Qwen 으로 (3단계)

- 긴급 확인 역할을 qwen 으로 바꾸면: 한국어 고정 한 번 → 기존 정확 매칭(`match_emergency_transcript`, wakeword_gate.py:23-55).
- Qwen 오기('엄청'·'먼저'·'몸초' 등)를 변형 목록에 넣지 않는다. 일상어라 대화 중 헛 비상정지를 낸다. 놓침은 측정으로 판단한다.
- 긴급어가 아닐 때만 감싸개가 문지기 1차(언어 자동)를 한 번 더 돌려, '말 없음' 이면 빈칸을 돌려준다. 빈칸이면 감시기는
  그 전사를 질문 답으로 넘기지 않는다(1164 행의 `text` 조건). 잡음이 '네' 로 둔갑해 출발로 이어지는 길만 막고, 감시기 코드는 그대로 둔다.
  진짜 '멈춰' 는 한 번에 끝나므로 확인 시간이 늘지 않는다.
- 비교 기준은 지금 운영 구성(small, 필터 없음)이다. 저장된 비상정지 녹음 79개(확정 37 · 기각 22 · 놓칠 뻔 19 · 이어 듣기 1)로 small 과 나란히 잰다.
  확정 37개는 small 이 이미 맞힌 것만 모인 묶음이라 small 에 유리하다. 나머지 42개는 사람이 들어 단 정답(`estop_labels.json`)으로 잰다.
- GOVERNANCE 상 E-stop 입력 경로 변경이다. 시험은 지금 하되, 시연에 켜기 전 팀 확인을 받는다.

### 4.5 실패하면 — 귀만 큰 오류로 멈춘다

음성 저장소에서 하는 것:

- qwen 으로 설정했는데 라이브러리·모델·적재가 실패하면 whisper 로 되돌아가지 않는다.
- 적재를 감시 스레드가 아니라 노드 시작 때 본 스레드에서 한다. 실패하면 큰 오류 로그를 남기고 0 이 아닌 코드로 끝낸다(지금은 스레드 안에서 죽어 노드가 살아 보인다).
- 실행 중 감시 스레드가 죽거나 연속 오류가 넘쳐도 노드를 끝낸다(생존 감시).

주행은 막지 않는다(10-15 사용자 결정). 지금 비상정지 노드는 물리 버튼·모터 통신만 끊김을 보고(emergency_stop_node.py:20, 45)
음성은 '멈춰' 가 올 때만 반응한다. 개발 중 음성을 끄고도 주행해야 하므로 이 구조를 유지한다. 대신 ⑫ 시작 로그와 귀 종료가
눈에 띄게 한다. 시연 모드가 따로 생기면 그때 '귀가 죽으면 출발 거부'를 다시 검토한다.

### 4.6 Realtime 을 글자 경로로 (2단계)

- 코드는 이미 있다. ⑬(오프라인)이 쓰는 구성 `VICA_INTENT_INPUT=text` + `VICA_LLM_PROVIDER=ollama` + `VICA_LLM_MODEL=midm2-mini` 이다.
- 개인정보 등급:

| 등급 | 구성 | 로봇 밖으로 나가는 것 |
|---|---|---|
| ① 시연 목표 | Qwen + 로컬 LLM(믿음) | 없음 |
| ② 예비 | Qwen + 클라우드 LLM(글자) | 글자만 |
| ③ 지금 | Realtime | 목소리 |

- ① 에서는 OpenAI 예비 경로도 꺼야 한다(`VICA_LLM_FALLBACK_*` 확인). 그래야 "아무것도 안 나간다"가 참이다.
- 확인할 것:
  - 믿음의 알려진 약점: 화장실 짐작, 숫자→호실(10-12 비교 26문장 중 나쁨 8). Qwen 의 숫자 글 표기 때문에 4.3 절 숫자 정리가 더 중요하다.
  - 첫 응답 7.7 s(미리 올려 두기 필요).
  - 메모리: 믿음 ≈ 2.7 GB + Qwen 1.7B ≈ 1.9 GB. whisper 두 벌이 빠지는 만큼 상쇄되지만 ⑬ 은 지금도 스왑을 쓴다.
  - 확인 질문·대기·취소·일시정지 흐름 전체.
- 지시문(숫자 규칙 등)을 바꾸면 사용자 승인을 받는다.
- 심사 대비(선택): 로봇이 저장하는 녹음(`~/vica_data/estop_clips` 등)의 보관 기간·삭제 기준도 정해 두면 답하기 쉽다.

## 5. 시험 계획

1. **단위 시험**: 가짜 transcribe_cpp 로 문지기·예외·시간 상한·실패 종료·숫자 정리. whisper 전제 시험 1개(`test_emergency_gate_log` 적재 시험)를 엔진 스위치에 맞게 고친다.
2. **녹음 재생**: 저장된 녹음을 실제 귀 판정 경로(`src/mic_check_replay.py`)에 Qwen 을 끼워 돌린다 — 칩 VAD·소리 크기 관문·짧은 답 구제를 거친 뒤에도 유령 승낙이 0 인지.
3. **팀원 목소리 녹음**: 비교기(`tools/stt_bench.py`)로 팀원 2~3명이 10분씩. 정답이 자동으로 붙는다. 09-24 정답 달기를 대신하고, '멈춰' 표본을 늘린다.
4. **정지 상태 실기**: 모든 노드를 켠 채 비교기 시나리오. 병원 소음은 실제 크기로, 로봇이 말하는 중 포함.
5. **주행 실기**(사용자와): 확인 질문 대답, '멈춰', 일시정지, 대기 요청. 회차마다 커밋.

합격 기준(제안):

| 기준 | 목표 |
|---|---|
| 원하지 않은 승낙 | 침묵·로봇 목소리·'멈춰' 묶음에서 '네/맞아' 0 |
| 정확도 | 정답 묶음에서 turbo 이상 |
| 긴급 | '멈춰' 놓침이 small 보다 늘지 않음, 헛 비상정지 0, 확인 시간 ≤ small + 0.2 s |
| 속도 | 대화 STT p90 ≤ 0.8 s(전체 스택 실행 중) |
| 안정 | 귀 스레드 사망 0, 2시간 대기 + 주행 1회 오류 0 |
| 자원 | 주행 중 RAM·스왑이 지금(turbo+small)보다 늘지 않음 |

## 6. 브랜치·배포

- 브랜치 `feat/stt-qwen-asr` 는 `after_feedback_waiting` e0bfc13 에서 땄다. 바꿀 코드(대화/긴급 STT 분리, 14a86c7)가 dev 에는 없다.

- 로봇 시험은 ⑫ 를 끄고 이 폴더에서 손으로 띄운다. 예: `VICA_STT_ENGINE=qwen VICA_VERIFY_STT_ENGINE=qwen … ros2 launch launch/vica_voice.launch.py map_id:=…`.
  명령 앞 값이 `.env` 보다 우선한다(load_dotenv override=False). `.env` 를 고치지 않으므로 평소 ⑫ 는 계속 whisper 다. ⑫ 둘을 동시에 띄우지 않는다.
- 비교기 3파일(`tools/stt_bench.py`·`tools/stt_bench_page.html`·`tests/test_stt_bench.py`)은 이 브랜치에 평가 도구로 커밋한다. 운영 폴더의 미추적 사본은 그 뒤 지운다(나중에 체크아웃이 막히지 않게).
- transcribe.cpp 는 커밋 e0d5e61 빌드를 이름 붙은 폴더로 복사해 고정한다(업스트림이 하루에도 바뀌고, `git pull`·재빌드에 운영 귀가 깨지지 않게). gguf sha256 과 빌드 절차는 `docs/jetson-setup.md` 에 적는다.
- 원격 푸시는 사용자가 말할 때(백업 권장). dev 머지는 주행 실기 통과 뒤. `after_feedback_waiting` 이 먼저 dev 에 들어가야 한다.

## 8. 위험

- 소음: 공개 자료에서는 잡음 속 turbo 가 가장 좋았다. 시연장 소음에서 순위가 뒤집힐 수 있다 → 4번 시험에서 실제 크기 소음.
- 메모리: 주행 중 이미 RAM 10~14 GB·스왑 최대 3.2 GB. 1.7B 가 무거우면 0.6B 로(모델 경로 한 줄).
- 긴 말: 1.7B 는 16 s 말에서 turbo 보다 느리다(2.64 vs 2.21 s). 문지기 2차까지 가면 더 걸린다.
- transcribe.cpp: 관리자 1명인 0.x 프로젝트, CUDA·aarch64 검증 기록이 없다 → 커밋·빌드 고정, CPU 와 결과 같은지 한 번 확인.
- 엔진 두 개 공존(1·3단계 중 하나만 qwen 일 때): CTranslate2 와 ggml CUDA 가 한 프로세스. 비교기에서는 문제없었다. ⑫ 종료 때 이미 있던 -6(SIGABRT)이 달라지는지 본다.
- 일정: 12일에 세 단계. 막히면 시연은 whisper + Realtime 으로 하고 `.env` 한 줄로 되돌린다.
