## 1. 중재 — 미션이 한 자리에서 "무엇을 읽을지" 정한다 (P2a)

### 1.1 지금의 겹침 원인

LLM 노드는 확인 질문·되묻기·잡담 답을 `/vica/tts_request` 로 직접 내고, 미션은 자기 거절·안내 문구를
같은 토픽에 낸다. 둘이 서로의 상태를 모르므로 "학과사무실로 안내해드릴까요?" 직후 "지금은 다른
응대 중입니다"가 이어 나온다(09-20 21:11·21:25). 원인은 입이 둘이라서가 아니라 **말과 상태가 다른
노드에 있어서**다.

### 1.2 계약 변경: `VicaIntent.reply` 는 "미션이 읽어도 되는 문장"

- LLM 노드는 **더 이상 `/vica/tts_request` 를 내지 않는다**(`request_for_intent` 폐지). 의도와 함께
  `reply` 를 실어 보내는 것으로 끝난다. `reply` 의 뜻은 "이 의도를 받아들이면 읽을 문장".
- 미션 `on_intent` 가 한 자리에서 정한다:
  - 제안(navigate/cancel/resume, need_confirm=True)을 받아들이면 → `Say(reply, expects_reply=True)`.
    상태가 안 맞으면(회전 중·안내 중·인사 답 대기) → 자기 거절 문구만 `Say`. **둘 중 하나.**
  - question / clarify(need_confirm=False) → `Say(reply)`; reply 가 "?"로 끝나면 `expects_reply=True`.
  - affirm / deny / wait / finish / 확정 navigate → reply 는 비어 있다(계약 그대로). 미션의 결과 문구.
  - unknown, reply 빈 문자열 → 침묵.
- 재청취 창(`/vica/listen_request`)은 미션이 `expects_reply` 로 지금처럼 연다. LLM 노드는 더 내지 않는다.
- LLM 노드의 "재청취 기각"·"생각 중" 신호는 그대로다(문장을 내지 않을 뿐).

### 1.3 줄 세우기

- 한 tick 에 한 마디: 위 규칙으로 미션은 한 사건에 문장 하나만 낸다(제안+거절 동시 발행이 구조적으로
  없어진다).
- TTS 노드: `response` 우선순위 항목이 **큐에서 5초 넘게 기다리면 버린다**(지난 상황을 말하지
  않는다). 큐 상한 8, 2초 중복 제거는 그대로. 새 토픽 없음.
- 끼어들기(barge-in)는 지금 기제 그대로 재생을 끊고 큐를 비운다(`/vica/tts_stop`).

### 1.4 인사 답 대기 중의 목적지 요청은 "네 + 목적지"로 받는다

지금은 `AWAITING_USER`(접근 질문 "안내를 받으시겠어요?"의 답 대기)에 navigate 가 오면
MSG_APPROACH_BUSY("지금은 다른 응대 중입니다")로 거절하고, 질문은 15초 뒤 "실례했습니다"로 접힌다
(09-20 21:11·21:25). 답할 사람은 그 사용자뿐이므로 거절할 이유가 없다.

- `on_intent`: 상태가 `AWAITING_USER` 이고 navigate(제안, need_confirm=True)가 오면 접근 질문을
  긍정으로 접고(`on_approach_answer(True)` 와 같은 정리: 시계·재청취 해제, 온보딩 되묻기 사다리 청산)
  곧바로 그 목적지의 확인 흐름(`CONFIRMING`)으로 간다. 읽는 문장은 reply(확인 질문) 하나.
- 확정 navigate(need_confirm=False)가 오면 — 모델이 앞선 제안을 기억해 확정으로 낸 경우 — 확인
  질문을 건너뛰지 않는다. 같은 목적지의 제안으로 강등해 확인 질문을 한 번 한다(안전: 접근 질문
  뒤 첫 출발은 반드시 확인을 거친다).
- 온보딩("손잡이는 …", "어디로 가고 싶으신가요?")은 이 경로에서 생략한다 — 목적지를 이미 말했다.

### 1.5 회전·탐색·복귀 중의 요청은 버리지 않고 들고 있는다

`TURNING`·`SEEKING`·`RETURNING` 중에 온 navigate 를 MSG_APPROACH_BUSY 로 버리는 대신 **보류 칸**에
둔다(09-20 21:24:52 "화장실로 가자"가 회전 중이라 버려진 사건).

- 보류 칸은 하나(최신 것만), 상한 10초(회전·탐색은 5~7초). 상한이 지나면 조용히 버린다.
- 동작이 끝나 `IDLE` 로 돌아오는 자리(회전 종료·탐색 종료·복귀 브레이크)에서 보류 요청을 꺼내
  `on_intent` 에 다시 넣는다 → 확인 질문으로 이어진다.
- 보류할 때 읽는 말은 짧은 접수 한마디("잠시만요.", 변형 가능). 진짜 받을 수 없는 경우만 남는다:
  `NAVIGATING` 중 새 목적지 → "지금 OO로 가는 중이에요. 바꾸시려면 취소라고 말씀해 주세요."
  (MSG_BUSY 의 문구를 이렇게 바꾼다 — 무엇을 하면 되는지를 말한다). "지금은 다른 응대 중입니다"
  문구는 없앤다.
- `ESTOPPED` 거절은 그대로.

### 1.6 관문

겹침 0회(09-20 21:11·21:25 장면 재현), 지연 증가 0(미션이 reply 를 읽는 경로는 지금의 LLM 노드
발행과 같은 한 hop), 인사 답 대기 중 목적지 요청 → 확인 질문 1회로 출발(재호출 0회), 회전 중 요청
→ 회전 뒤 확인 질문. 미션 파라미터 `speak_reply:=true` 로 켜고, false 면 옛 동작(LLM 노드가 직접
발행). 1.4·1.5 는 같은 플래그 아래 둔다.

## 2. 말투 — 미리 생성한 변형과 오디오 캐시 (P2b)

### 2.1 두 등급의 지연 예산

| 등급 | 무엇 | 예산 | 방법 |
| --- | --- | --- | --- |
| 즉시 | 출발·거리·도착·도착 질문·시간 질문·대기 확답·취소·종료·인사·온보딩 등 미션 문구 30종 | **0.2 s** | 미리 생성한 변형 + 미리 합성한 오디오 |
| 대화 | 사용자 말에 대한 답(확인 질문·되묻기·잡담 답) | 1.5 s | 지금처럼 Realtime 실시간(`set_intent.reply`) |

지금 고정 문구는 캐시 녹음이라 0.1 s 에 나간다. 이 예산을 지키지 못하는 설계는 채택하지 않는다.

### 2.2 변형 생성 (P2b-1)

- LLM 노드가 기동 시(그리고 목적지 파일이 바뀌면) 문구 종류 30종마다 **변형 2~3개**를 모델로
  만들어 `~/vica_data/state/<map_id>/line_variants.json` 에 저장한다. 장소·분 같은 사실은 `{place}`,
  `{minutes}` 자리표시자로 남긴다. 생성은 백그라운드, 약 90 호출·2분, 파일이 있으면 건너뛴다.
- 미션은 이 파일을 읽어 문구를 낼 때 변형 하나를 고르고 사실을 채운다(조사는 기존 `_josa_euro`).
  파일이 없거나 항목이 없으면 틀 문장. 파라미터 `compose_variants:=true`, false 면 틀 문장만.
- **내용 검증(생성 시 코드가 확인)**: 자리표시자 보존, 60자 이내, 틀 문장에 없는 숫자·층·장소 없음,
  질문이면 "?"로 끝남, 사용자 발화 인용 없음(따옴표 금지). 실패한 변형은 버린다.
- 출발 시 미션은 그 안내에서 쓰일 문장(도착·도착 질문·시간 질문·확답)을 `/vica/tts_prewarm`
  (`std_msgs/String`)으로 TTS 노드에 보내 **재생 없이 합성만** 해 둔다. TTS 노드에는 이미 합성 캐시
  (`SynthCache`)가 있어 구독 하나를 더하는 일이다.

### 2.3 맥락 반영 문장 (P2b-2, 선택)

"배가 아프시군요. 화장실로 안내해드릴까요?"처럼 사용자 말을 받아 주는 문장은 지금도 LLM 노드의
`reply` 로 나온다(대화 등급). 미션 문구까지 맥락을 반영하고 싶을 때만 ROS 서비스
`/vica/compose_line`(요청: kind·template·facts_json·budget_ms → 응답: text·source)을 두고, 미션이
비동기로 호출해 1.5 s 안에 오면 그 문장, 아니면 변형/틀 문장을 읽는다. P2b-1 실기에서 "변형만으로
말투가 충분하다"고 판단되면 만들지 않는다.

### 2.4 대화 기록

실제로 재생된 문장은 `/vica/tts_done` 으로 돌아와 AI 줄로 기록된다(09-20 구현). 변형이든 틀 문장이든
읽힌 쪽만 남는다. 기록 초기화 규칙(대기 중 보존, `return_home_sent` 에만 비움)은 그대로.

## 3. 로봇 대장 — 미션이 적고 방송한다 (P1)

### 3.1 무엇을 적나

| 줄 | 값 | 출처 |
| --- | --- | --- |
| 건물·층 | `로봇관`, `4` | 지도 폴더의 `map.yaml`(`building`, `floor`) — 지도 = 한 층 |
| 지금 있는 곳 | `407호 앞` / `407호와 화장실 사이` / `위치 미확인` | AMCL 좌표 vs 등록 목적지 좌표. 3.0 m 안이면 "OO 앞", 아니면 가장 가까운 두 곳 "사이". 초기 위치 전(포즈 미수신·공분산 큼)은 미확인 |
| 가는 중인 곳 | 목적지 name | 출발 시 기록, 도착·실패·취소 시 비움 |
| 직전에 간 곳 · 도착 시각 | name, epoch | 도착(`goal_succeeded`) |
| 하려다 만 곳 | name | 확인 대기까지 갔다가 거절·취소·시간초과·무응답으로 안 간 곳. 다음 출발 시 비움 |
| 대화 단계 | `idle` / `awaiting_user` / `confirming` / `seeking` / `navigating` / `asking_next` / `asking_wait_time` / `waiting` / `returning` | 미션 상태 그대로 |
| 대기 | 요청 분, 남은 초 | WAITING 진입 시 |

### 3.2 전달과 보존

- `vica_interfaces/msg/RobotState.msg` 에 칸을 늘린다: `string dialog_state`, `string place_here`,
  `float32 place_here_dist_m`, `string active_destination`, `string last_destination`,
  `int32 last_arrived_age_sec`, `string aborted_destination`, `int32 wait_minutes`, `int32 wait_left_sec`.
  기존 칸(`current_floor`, `current_building`, `is_moving`, `is_paused`)은 유지하고 층·건물은 `map.yaml`
  로 채운다(launch 인자는 있으면 우선).
- 미션은 지금처럼 1 Hz 로 `/vica/robot_state` 를 낸다. 대장이 바뀔 때마다
  `~/vica_data/state/<map_id>/ledger.json` 에 적고, 기동 시 읽어 "직전에 간 곳·하려다 만 곳"을 복원한다.
  "지금 있는 곳"은 복원하지 않는다(초기 위치 뒤 좌표로 다시 계산).
- LLM 노드의 `SituationBoard` 는 `/vica/robot_state` 를 읽어 채우는 `LedgerView` 로 바뀐다. 새 칸이
  비어 오면(옛 미션) 지금의 goal-event 추정을 그대로 쓴다(호환). 지시문 맨 뒤 `[지금 상황]` 블록의
  줄이 3.1 의 일곱 줄이 된다. "답을 기다리는 중" 표시는 유지.
- **원천 차단**: 대화 단계가 지시문에 들어가므로 모델은 미션이 거절할 제안(회전 중·안내 중·인사 답
  대기 중의 navigate)을 애초에 내지 않는다. 1절의 중재는 그래도 새는 것을 막는 그물이다.

### 3.3 질문 → 답의 출처

"몇 층이야?" → 건물·층 / "지금 어디 있지?" → 지금 있는 곳 / "어디 가려고 했더라?" → 하려다 만 곳
(더 오래된 일은 4절) / "지금 어디 가?" → 가는 중인 곳 / "OO는 몇 층?" → 목적지 목록의 방별 층.

## 4. 사건 일지와 찾아보기 도구 (P3 — 계측으로 필요가 확인되면)

### 4.1 착수 조건

P1·P2 실기에서 "대장으로 못 답한 기억 질문"(아까 처음에·몇 번·몇 분 전 같은 과거 순서·횟수·시간)을
센다. 실기 회차당 2건 이상이면 착수한다.

### 4.2 일지

- LLM 노드가 적는다. 파일 `~/vica_data/field/journal-YYYYMMDD.jsonl`, 한 줄 = 한 사건:
  `{"t": "10:43:12", "session": 7, "kind": "depart", "place": "407호"}`. kind 는 미션 사건(출발·도착·
  대기·취소·종료·귀가, `/vica_goal_event` 와 `/vica/tts_done` 에서) + 사용자 쪽 `wake`, `propose`,
  `confirm`, `deny`, `wait_request`(분).
- 사실만 적는다. 모델이 지은 문장은 적지 않는다. 파일 쓰기 실패는 로그만.
- `session` 은 대화 회차. 안내가 대기 없이 끝나 미션이 홈으로 갈 때(`return_home_sent`) 하나 오른다.

### 4.3 도구

- Realtime 도구 둘: `set_intent`(기존), `recall_journal`
  (`{"scope": "session"|"today", "kinds": [str], "place": str, "limit": int<=10}` → 최근순 최대 10줄).
- 흐름(`RealtimeIntentClient.ask`): 1차 응답 `tool_choice: "required"`. 모델이 `recall_journal` 을 부르면
  코드가 찾아 `function_call_output` 을 붙여 2차 응답을 만들고 `set_intent` 를 강제한다. **발화당 조회
  최대 1회.**
- 지시문 규칙: "`[지금 상황]` 에 답이 있으면 찾지 마라. 과거의 순서·횟수·시간을 물으면 찾아라."
- 로그 `[RT] … tool=recall(session, 4줄)` 로 호출 여부·건수를 남긴다.

## 5. 안전·오류 처리

- 긴급어·비상 멈춤·이동 실패 등 안전·거절 문구는 지금처럼 미션 고정 문구. 변형을 만들지 않는다
  (MSG_ESTOPPED, MSG_ESTOP_RELEASED, MSG_NAV_FAILED, MSG_NAV_NOT_READY, MSG_ESTOP_REJECT, MSG_UNKNOWN_DEST,
  MSG_PRIVATE_DEST, MSG_NOT_APPROACHABLE, MSG_POSE_INVALID, 앱 배달 모드 문구).
- LLM 노드 부재: 미션은 원래 자기 문구를 자기가 읽으므로 안내가 끊기지 않는다. 사용자 말에 대한
  답만 없다(지금과 같음).
- 인터넷 부재·느림: 변형은 파일에 있어 영향 없다. `compose_line`(P2b-2) 은 시간 초과면 변형/틀 문장.
- 변형 생성 실패·검증 실패: 그 항목은 틀 문장. 생성 중 오류는 로그만, 노드는 죽지 않는다(09-20 로거
  사건의 원칙).
- 되돌리기: 미션 `speak_reply:=false`(1절 이전), `compose_variants:=false`(변형 이전),
  `.env` `VICA_INTENT_INPUT=text`(의도는 whisper 경로). 셋 다 독립.

## 6. 시간 상수

| 값 | 재는 구간 | 만료 시 | 근거 |
| --- | --- | --- | --- |
| 0.2 s | 즉시 등급 문구: 사건 → 재생 시작 | 예산 위반 = 설계 결함 | 지금 캐시 녹음 0.1 s 와 같은 체감 |
| 1.5 s | 대화 등급: 사용자 발화/`compose_line` → 문장 | 틀 문장 | 모델 응답 중앙값 1.3 s |
| 5 s | TTS 큐의 `response` 대기 | 버림 | 지난 상황을 말하지 않는다 |
| 6 s (`VICA_REALTIME_TIMEOUT`) | 소리 발송 → 의도 | whisper 경로가 답, 30 s 생략 | 09-20 7~8 s 꼬리 2건 |
| 8 s | 질문 재생 완료 → 답 | 같은 질문 1회 → 예고 → 종료 | Alexa 와 동일. 귀 홀드 중 정지 |
| 3 s (예고) | 떠나기 예고 → 출발 | 귀가 | 기존 값 |
| 30 s | Realtime 실패 → 재시도 | 재시도 | 복도 음영에서 발화마다 6 s 대기 방지 |

개정 1의 3 s 접수 보험·번호 왕복은 폐기됐다(미션이 자기 문구를 자기가 읽는다).

## 7. 시험과 합격선

- 단위: 미션 `on_intent` 중재(제안 수락 → reply 발화, 거절 → 거절 문구만, question → reply, 빈 reply →
  침묵), AWAITING_USER 의 navigate → CONFIRMING(확정 navigate 는 제안으로 강등), TURNING/SEEKING/
  RETURNING 의 navigate 보류 → IDLE 복귀 시 재투입·10초 만료, `request_for_intent` 폐지 뒤 LLM 노드가
  TTS 를 내지 않음, TTS 큐 5초 폐기, 변형 검증 규칙
  5종, 변형 채우기(조사), 대장 계산(좌표→앞/사이/미확인, 복원), `LedgerView` 호환, (P3) 일지 회차·
  도구 필터·2회전 흐름.
- 실 API 스모크: 변형 생성 30종·검증 통과율, (P2b-2) `compose_line` 예산.
- 실기 대본: 09-20 21:11·21:25 겹침 장면 재현 / 도착 즉시 안내 / "우리 몇 층?"·"어디 있지?"·"어디
  가려 했지?" / 10분 대기 뒤 같은 질문 / 복도 오프라인 도착 / 질문 중 끼어들기 / 변형이 매번 다르게
  들리는지.
- 합격선: 겹침 0회 · 즉시 등급 문구 재생 시작 ≤ 0.2 s · 오프라인 안내 누락 0 · 무응답 재질문 1회 뒤
  종료 · 대장 질문 3종 정답 · 변형 검증 실패율 < 10 %.
