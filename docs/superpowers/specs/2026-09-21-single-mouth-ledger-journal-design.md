## 1. 대화 흐름 — 비카의 일곱 가지 태도 (P2a)

역할극에서 사장님이 연기한 비카는 일관되게 이렇게 행동했다. 이 일곱 줄이 1절의 뼈대다.

1. 부르면 바로 답한다. 2. 사실을 말하고 곧장 제안한다. 3. 확정은 명시적 긍정에만. 4. 변경은 확인 한 번.
5. 불확실하면 가장 비슷한 것으로 확인 질문. 6. 옆에 있는 동안은 계속 듣는다. 7. 떠날 땐 예고한다.

### 1.1 호출에는 관문이 없다

- 지금은 인사 질문("안녕하세요? … 안내를 받으시겠어요?")을 여는 길이 셋이다: 카메라 감지기가 걸어가
  도착(정상 접근), 근접 호출, **"비카야" 호출이 손잡이 쪽에서 오면 곧장**(`on_wake_doa`, 09-11). 셋째
  때문에 감지기 노드를 켜지 않아도 인사 질문이 나온다.
- 바꿈: **호출은 인사 질문을 열지 않는다.** 웨이크워드 노드의 "네?"(캐시 녹음, 0초)만 나가고 듣는다.
  호출에 용건이 있으면("비카야, 화장실 어디야") 그 용건이 곧바로 의도 경로로 간다. 호출 방향이 뒤가
  아니면 지금처럼 그쪽으로 돌되, 돌고 나서도 인사 없이 듣는다. 미션 파라미터 `wake_greeting:=false`
  (기본). 감지기 접근 두 길은 지금 그대로 — 로봇이 먼저 말을 건 상황이라 인사가 맞다.
- 온보딩("손잡이는 진동 오는 쪽…")은 손잡이 감지가 되면 그 순간에. 그 전까지는 **출발 순간 한 줄**
  ("출발할게요. 진동 오는 쪽 손잡이를 잡아 주세요.") — 변형 대상.
- 감지기 접근의 인사말 도중 끼어들기(1.6)로 용건이 오면 인사를 끊고 그 용건으로 간다.

### 1.2 중재 — 미션이 한 자리에서 "무엇을 읽을지" 정한다

- LLM 노드는 **`/vica/tts_request` 를 내지 않는다**(`request_for_intent` 폐지). 의도와 함께 `reply` 를
  실어 보낸다. `reply` = "이 의도를 받아들이면 읽을 문장".
- 미션 `on_intent` 가 한 자리에서 정한다: 제안(navigate/cancel/resume, need_confirm=True)을 받아들이면
  `Say(reply, expects_reply=True)`, 상태가 안 맞으면 자기 문구만 — **둘 중 하나**. question/clarify 는
  `Say(reply)`("?"로 끝나면 expects_reply). affirm/deny/wait/finish/확정 navigate 는 reply 가 비어 있고
  미션의 결과 문구. unknown·빈 reply → 침묵.
- 재청취 창은 미션이 `expects_reply` 로 지금처럼 연다. LLM 노드의 "재청취 기각"·"생각 중"은 그대로.
- TTS 노드: `response` 항목이 큐에서 5초 넘게 기다리면 버린다. 큐 상한 8·2초 중복 제거 그대로.
- 파라미터 `speak_reply:=true`, false 면 옛 동작.

### 1.3 확정은 명시적 긍정에만, 변경은 확인 한 번

- "네… 근데 멀어요?"처럼 긍정 뒤에 질문이 붙으면 확정하지 않고 질문에 답한다(모델 규칙, 지금 지시문).
- **주행 중 새 목적지**: "지금 OO로 가는 중이에요. XX로 바꿀까요?" 한 번 묻고, 긍정이면 현재 goal 을
  접고 XX 로 간다(확인은 이미 했으므로 곧장 출발). 부정이면 계속. MSG_BUSY("먼저 취소해 주세요")와
  MSG_APPROACH_BUSY("지금은 다른 응대 중입니다")는 없앤다.
- **주행 중 종료 요청**("됐어요, 여기서 그만 갈게요"): "이제 안내가 필요 없으신가요?" 한 번 묻고 긍정이면
  종료·귀가. 지금의 취소 확인과 같은 흐름, 문구만 변형.

### 1.4 회전·탐색·복귀 중의 요청은 들고 있는다

`TURNING`·`SEEKING`·`RETURNING` 중에 온 navigate 는 보류 칸(최신 하나, 상한 10초)에 두고, 동작이 끝나
`IDLE` 로 돌아오는 자리에서 꺼내 `on_intent` 에 다시 넣는다. 보류할 때 "잠시만요." 한마디. 회전 중의
**질문**은 보류 없이 바로 답한다(09-21 역할극: 회전 중 "손잡이 어디 잡아요?").

### 1.5 옆에 있는 동안은 계속 듣고, 떠날 땐 예고한다

- **도착 뒤 침묵**: 질문 재생 완료 뒤 8초 침묵이면 "안내가 더 필요 없으시면 돌아가도 될까요?"(변형)
  를 묻고 **10초** 기다린다. 긍정·침묵이면 "돌아가겠습니다" 한 줄 뒤 귀가, 부정·목적지·대기 요청이면
  이어 간다. 지금의 "같은 질문 되묻기 → 떠나기 예고" 사다리를 이 두 단으로 바꾼다(2단 유지).
- **대기 진입 뒤 30초는 귀를 열어 둔다**: "잠깐만요, 노크해 볼게요" 뒤 15초 만에 "거기로 가요"가 오는
  장면. 대기로 들어가도 사용자 방향(DOA 부채꼴)의 말은 30초 동안 호출 없이 받는다. 30초 뒤엔 지금처럼
  "비카야"로.
- **대기 만료**: "5분이 지나 돌아가겠습니다." 한 줄(변형) 뒤 귀가. 지금은 예고 없이 귀가.
- 복귀 중 재호출은 지금 기제(복귀 브레이크)대로 멈춰 듣고, 대화 기록이 살아 있으므로 "아까 화장실
  가기로 했잖아요"를 잇는다.

### 1.6 끼어들기는 로봇이 말하는 중 언제나

지금 음성 barge-in 은 "질문 재생 중"에만 발동한다. 인사말·안내 문구 중에도 사용자 방향의 발화가
칩 VAD·AND·과반 창을 통과하면 재생을 끊고 듣는다(웨이크워드 노드 `_followup_armed` 조건 완화).
자책골(로봇이 제 말을 끊음) 방어는 09-21 되살린 설정 그대로(REQUIRE_BOTH·MIN_HITS 3·DOA 180±60).

### 1.7 주행 중 호출은 사용자 방향만

안내 중(`NAVIGATING`·`WAITING`)에 온 "비카야"는 DOA 가 사용자 부채꼴 안일 때만 받는다. 행인의
"비카야, 안녕!"은 "네?"도 없이 무시한다(웨이크워드 노드가 `/vica/robot_state.is_moving` 과 DOA 로 판정).

### 1.8 즉시 정지 낱말은 모델을 거치지 않는다

- "멈춰·정지·스톱": 긴급어 경로(로컬 whisper → 안전 노드) 그대로.
- "잠깐·잠깐만·잠시만": 일시정지. 소리 모드에서도 **웨이크워드 노드의 로컬 규칙**으로 즉시 pause 를
  낸다(모델 판단을 기다리지 않는다). 09-20 전결 전환 때 뺐던 pause 지름길을 이 자리에 되살린다.
- 음성 정지의 **해제 정책 B**(P2c, Safety 노드): 래치 원인이 음성(STT)뿐이면 사용자의 재개 발화
  ("괜찮아요, 다시 가요")로 해제하고 관리자 앱에 "음성 정지·음성 해제" 알림을 보낸다. 버튼·앱·통신
  원인이 섞여 있으면 지금처럼 관리자만. 기존 `AutoRecoveryPolicy`(통신 원인만 자동 복구)와 같은
  자리에 "STT 원인만 음성 해제"를 더한다. GOVERNANCE·루트 CLAUDE.md 의 "STT reset 은 관리자만" 문장을
  이 결정으로 갱신한다.

### 1.9 불확실하면 가장 비슷한 것으로 확인 질문

소음에 "학과 사물실"처럼 들리면 목록의 가장 비슷한 이름으로 **확인 질문**을 한다("학과사무실로
안내해드릴까요?"). 목록에 비슷한 것도 없을 때만 되묻는다. 지시문 한 줄 + 코드의 근사 매칭은 지금
`match_destination` 그대로.

### 1.10 관문

겹침 0회(09-20 21:11·21:25 재현) · 호출 → 용건까지 재호출 0회 · 회전 중 요청 → 회전 뒤 확인 질문 ·
주행 중 변경 → 확인 1회로 전환 · 도착 뒤 침묵 → "돌아가도 될까요?" 뒤 10초 · 대기 진입 30초 안 발화
수신 · 인사말 중 끼어들기 성공 · 행인 호출 무시 · "잠깐" 1초 안 정지.

## 2. 말투 — 미리 생성한 변형과 오디오 캐시 (P2b)

### 2.1 두 등급의 지연 예산

| 등급 | 무엇 | 예산 | 방법 |
| --- | --- | --- | --- |
| 즉시 | 출발·거리·도착·도착 질문·시간 질문·대기 확답·취소·종료·예고 등 미션 문구 30종 | **0.2 s** | 미리 생성한 변형 + 미리 합성한 오디오 |
| 대화 | 사용자 말에 대한 답(확인 질문·되묻기·잡담 답) | 1.5 s | 지금처럼 Realtime 실시간(`set_intent.reply`) |

지금 고정 문구는 캐시 녹음이라 0.1 s 에 나간다. 이 예산을 지키지 못하는 설계는 채택하지 않는다.

### 2.2 변형 생성 (P2b-1)

- LLM 노드가 기동 시(그리고 목적지 파일이 바뀌면) 문구 종류 30종마다 **변형 2~3개**를 모델로 만들어
  `~/vica_data/state/<map_id>/line_variants.json` 에 저장한다. 장소·분 같은 사실은 `{place}`, `{minutes}`
  자리표시자로 남긴다. 생성은 백그라운드, 약 90 호출·2분, 파일이 있으면 건너뛴다.
- 미션은 이 파일을 읽어 문구를 낼 때 변형 하나를 고르고 사실을 채운다(조사는 기존 `_josa_euro`).
  파일이 없거나 항목이 없으면 틀 문장. 파라미터 `compose_variants:=true`, false 면 틀 문장만.
- **내용 검증(생성 시 코드가 확인)**: 자리표시자 보존, 60자 이내, 틀 문장에 없는 숫자·층·장소 없음,
  질문이면 "?"로 끝남, 사용자 발화 인용 없음(따옴표 금지). 실패한 변형은 버린다.
- 출발 시 미션은 그 안내에서 쓰일 문장(도착·도착 질문·시간 질문·확답)을 `/vica/tts_prewarm`
  (`std_msgs/String`)으로 TTS 노드에 보내 **재생 없이 합성만** 해 둔다(`SynthCache` 재사용, 구독 하나).

### 2.3 맥락 반영 문장 (P2b-2, 선택)

미션 문구까지 맥락을 반영하고 싶을 때만 ROS 서비스 `/vica/compose_line`(kind·template·facts_json·
budget_ms → text·source)을 두고 미션이 비동기 호출, 1.5 s 안에 오면 그 문장, 아니면 변형/틀 문장.
P2b-1 실기에서 변형만으로 충분하면 만들지 않는다.

### 2.4 대화 기록

실제로 재생된 문장은 `/vica/tts_done` 으로 돌아와 AI 줄로 기록된다. 기록 초기화는 안내가 대기 없이
끝날 때(`return_home_sent`)뿐 — 대기 중·복귀 중 재호출에서 "아까 화장실 가기로 했잖아요"가 통한다.

## 3. 로봇 대장 — 미션이 적고 방송한다 (P1)

### 3.1 무엇을 적나

| 줄 | 값 | 출처 |
| --- | --- | --- |
| 건물·층 | `로봇관`, `4` | 목적지 폴더 `~/vica_data/destinations/<map_id>/map.yaml`(`building`, `floor`) — 지도 = 한 층 |
| 지금 있는 곳 | `407호 앞` / `407호와 화장실 사이` / `위치 미확인` | AMCL 좌표 vs 등록 목적지 좌표. 3.0 m 안이면 "OO 앞", 아니면 가장 가까운 두 곳 "사이". 초기 위치 전은 미확인 |
| 가는 중인 곳 | 목적지 name | 출발 시 기록, 도착·실패·취소 시 비움 |
| 직전에 간 곳 · 도착 시각 | name, epoch | 도착(`goal_succeeded`) |
| 하려다 만 곳 | name | 확인 대기까지 갔다가 거절·취소·시간초과·무응답으로 안 간 곳. 다음 출발 시 비움 |
| 대화 단계 | `idle` / `awaiting_user` / `confirming` / `seeking` / `navigating` / `asking_next` / `asking_wait_time` / `waiting` / `returning` | 미션 상태 그대로 |
| 대기 | 요청 분, 남은 초 | WAITING 진입 시 |
| 시각 | `15:40` | LLM 노드 시스템 시계(미션 방송에는 없음) |
| 배터리 | `80 %` / `모름` | 전원 측정기(INA228)가 고장이라 시스템 값이 있으면 그것, 없으면 "모름" |

**건물 디렉터리**: 다른 층의 장소("3층 세미나실")는 `~/vica_data/destinations/directory.yaml`
(하나, `building` 칸으로 구분, name·floor)로 안다. 이 층이 아니면 "3층에 있다, 층 이동은 못 한다"고 말하고 등록 목적지
**엘리베이터**를 제안한다. 지시문의 목적지 목록 뒤에 "다른 층" 블록으로 붙는다.

### 3.2 전달과 보존

- `vica_interfaces/msg/RobotState.msg` 칸 추가: `string dialog_state`, `string place_here`,
  `float32 place_here_dist_m`, `string active_destination`, `string last_destination`,
  `int32 last_arrived_age_sec`, `string aborted_destination`, `int32 wait_minutes`, `int32 wait_left_sec`,
  `int32 battery_pct`(-1 = 모름). 기존 칸 유지, 층·건물은 `map.yaml` 로 채운다(launch 인자 우선).
- 미션은 1 Hz `/vica/robot_state` 그대로. 대장이 바뀔 때마다 `~/vica_data/destinations/<map_id>/ledger.json`
  (home.yaml 과 같은 폴더)에 적고 기동 시 "직전에 간 곳·하려다 만 곳"을 복원한다. "지금 있는 곳"은 복원하지 않는다.
- LLM 노드의 `SituationBoard` 는 `/vica/robot_state` 를 읽는 `LedgerView` 로 바뀐다(새 칸이 비어
  오면 지금의 goal-event 추정, 호환). 시각은 LLM 노드가 직접 넣는다. 지시문 맨 뒤 `[지금 상황]` 블록.
- **원천 차단**: 대화 단계가 지시문에 있으므로 모델은 회전 중·안내 중의 제안을 애초에 내지 않는다.
  1절의 중재는 그물이다.

### 3.3 질문 → 답의 출처

"몇 층이야?" → 건물·층 / "지금 어디 있지?" → 지금 있는 곳 / "어디 가려고 했더라?" → 하려다 만 곳
(더 오래된 일은 4절) / "지금 어디 가?" → 가는 중인 곳 / "OO는 몇 층?" → 목적지 목록·건물 디렉터리 /
"몇 시야?" → 시각 / "배터리?" → 배터리 / "OO로 갈 수 있어?"(다른 층) → 디렉터리 + 엘리베이터 제안.

## 4. 사건 일지와 찾아보기 도구 (P3 — 계측으로 필요가 확인되면)

### 4.1 착수 조건

P1·P2 실기에서 "대장으로 못 답한 기억 질문"(아까 처음에·몇 번·몇 분 전 같은 과거 순서·횟수·시간)을
센다. 실기 회차당 2건 이상이면 착수한다.

### 4.2 일지

- LLM 노드가 적는다. 파일 `~/vica_data/field/journal-YYYYMMDD.jsonl`, 한 줄 = 한 사건:
  `{"t": "10:43:12", "session": 7, "kind": "depart", "place": "407호"}`. kind 는 미션 사건(출발·도착·
  대기·취소·종료·귀가, `/vica_goal_event` 와 `/vica/tts_done` 에서) + 사용자 쪽 `wake`, `propose`,
  `confirm`, `deny`, `wait_request`(분). 사실만 적는다. 파일 쓰기 실패는 로그만.
- `session` 은 대화 회차. `return_home_sent` 에 하나 오른다.

### 4.3 도구

- Realtime 도구 둘: `set_intent`(기존), `recall_journal`(`scope` session|today, `kinds`, `place`, `limit`≤10).
- 흐름: 1차 `tool_choice: "required"`; `recall_journal` 이면 코드가 찾아 `function_call_output` 을 붙여
  2차 응답에서 `set_intent` 강제. **발화당 조회 최대 1회.**
- 지시문: "`[지금 상황]` 에 답이 있으면 찾지 마라. 과거의 순서·횟수·시간을 물으면 찾아라."
- 로그 `[RT] … tool=recall(session, 4줄)`.

## 5. 안전·오류 처리

- 긴급어("멈춰·정지·스톱")는 로컬 whisper → 안전 노드 그대로. 안전·거절 문구 9개(MSG_ESTOPPED,
  MSG_ESTOP_RELEASED, MSG_NAV_FAILED, MSG_NAV_NOT_READY, MSG_ESTOP_REJECT, MSG_UNKNOWN_DEST, MSG_PRIVATE_DEST,
  MSG_NOT_APPROACHABLE, MSG_POSE_INVALID)와 앱 배달 모드 문구는 변형을 만들지 않는다.
- 음성 정지 해제 B(1.8)는 Safety 노드의 reset 정책 변경이다. `test_emergency_latch`·`test_reset_sequence`·
  `test_auto_recovery` 와 같은 급의 시험과 실기(주행 중 "멈춰" → "다시 가요" 해제 / 버튼 원인 섞임 →
  거부)를 거친 뒤에만 켠다. 파라미터 `voice_release:=false` 기본, 실기 통과 뒤 true.
- LLM 노드 부재: 미션은 자기 문구를 자기가 읽으므로 안내가 끊기지 않는다. 사용자 말의 답만 없다.
- 인터넷 부재·느림: 변형은 파일에 있어 영향 없다. 원고는 whisper 경로(로컬 모델)가 대신.
- 변형 검증 실패·파일 쓰기 실패: 틀 문장·로그만. 어떤 로그·파일 오류도 노드를 죽이지 않는다.
- 되돌리기: `wake_greeting`, `speak_reply`, `compose_variants`, `voice_release`(미션·Safety 파라미터),
  `.env` `VICA_INTENT_INPUT=text`. 전부 독립.

## 7. 시험과 합격선

- 단위(미션): `wake_greeting=false` 에서 wake_doa 가 AWAITING_USER 로 가지 않음, 중재 4갈래, 주행 중
  변경 확인 → goal 교체, 종료 확인, 보류 칸(재투입·10초 만료·질문은 즉시), 도착 뒤 침묵 2단(8 s → 되묻기
  → 10 s → 귀가), 대기 만료 예고, 대장 계산·복원·시각·배터리.
- 단위(음성): `request_for_intent` 폐지, TTS 5초 폐기, `tts_prewarm`, 변형 검증 5종·채우기, `LedgerView`
  호환, 웨이크워드 노드의 "잠깐" 로컬 pause·주행 중 DOA 관문·인사말 중 barge-in.
- 단위(Safety, P2c): STT 원인만인 래치의 음성 해제, 원인 섞임 거부, 관리자 알림 발행.
- 실 API 스모크: 변형 생성 30종·검증 통과율.
- 실기 대본(역할극 3장면 재현): 호출+용건 → 확인 1회 / 인사말 중 끼어들기 / 회전 중 질문·요청 / 주행 중
  변경 "바꿀까요?" / "잠깐" 즉시 정지 / "멈춰" → "다시 가요" 해제(P2c) / 도착 뒤 침묵 2단 / 대기 진입 뒤
  15초 만의 요청 / 5분 만료 예고 / 소음 속 "학과 사물실" / 다른 층 세미나실 → 엘리베이터 제안 / 행인
  "비카야" 무시 / 오프라인에서 "어디 갔었지? 몇 층?".
- 합격선: 겹침 0 · 즉시 등급 ≤ 0.2 s · 재호출 0(용건 있는 호출) · 오프라인 안내 누락 0 · 대장 질문 5종
  정답 · 변형 검증 실패 < 10 % · 자책골 0(barge-in 확대 뒤).
