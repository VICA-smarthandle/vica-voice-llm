# 소프트웨어 에코 제거 — 젯슨에서 로봇 말소리 줄이기 (설계)

작성 2026-11-18. 결정 기록: 11-18 대화(사용자 = 음성·LLM 담당). 측정 자료와 스크립트는
`~/vica_data/mic_checks/20261118-aec/`(6채널 녹음 `aec_153103_user1.wav`, `history/README.md`, `spike/`, `history/speex_*.py`).

## 1. 왜

사용자 관찰(11-18): 오늘 저장된 호출 소리(`~/vica_data/wake_clips`)에 로봇 말소리가 크게 들린다.

원인(11-18 측정·지난 점검 녹음 대조):

- reSpeaker 칩(XVF-3000)의 에코 제거는 지금 스피커(Soundcore 2, AUX → reSpeaker 3.5 mm)의 말소리를 지우지 못한다.
  스피커 소리가 칩의 기준 신호(ch5)보다 **118~122 ms 늦게** 마이크에 오기 때문이다. 말소리 제거량 0.3 dB.
- 이 지연은 새로 생긴 것이 아니다. 점검 6단계 녹음에서 재생 시작 → 소리 도착 시간이 10-13 ~ 11-18 전부 1.24~1.29 s 다.
- 칩 설정에는 지연·처리 시간 길이를 정하는 항목이 없다(Seeed `tuning.py` 표 40개).
- 그래서 스피커에서 마이크로 들어오는 소리가 커지면 그대로 남는다. 남은 로봇 소리 ÷ 원본(ch0, 같은 멘트 8개):
  10-22 0.09 · 10-24 0.10 · 10-29 0.04 · 11-04 0.20 · **11-18 0.47**.
- 스피커는 바꾸지 않는다(사용자 11-18).

오프라인 시험(오늘 6채널 녹음 한 개, `libspeexdsp` 를 ctypes 로 부름):

| 항목 | 결과 |
|---|---|
| 로봇 말소리 줄임(ch0 에 적용, 기준 100 ms 늦춤, 필터 256 ms) | −8.6 ~ −9.5 dB |
| 학습에 걸리는 시간 | 로봇 말 첫 2 s −1.9 dB → 2~4 s −7.7 dB → 그 뒤 −8.4 dB |
| 사람 말만 있을 때 변화 | −0.1 dB |
| 로봇 말 위에 사람 말을 겹쳤을 때(합성 1건) 사람 말 보존 | −0.5 dB(닮음 0.94), 로봇÷사람 −2.0 → −10.7 dB |
| 같은 겹침에서 호출 모델 v2 점수("비카야 화장실 가자") | 처리 전 0.00(놓침) → 처리 뒤 0.98(확정). 사람만일 때 0.97 |
| 처리 시간(젯슨) | 80 ms 블록당 0.75 ms(한 코어의 0.9 %) |
| 필터가 지연보다 짧을 때(32~96 ms, 기준 그대로) | 0.0 dB — 칩이 못 지우는 것과 같은 모습 |

## 2. 목표 · 하지 않는 것 · 실패로 보는 것

- 목표: 호출 모델·긴급어 모델·받아쓰기·저장 소리가 받는 ch0 에서 로봇 말소리를 약 9 dB 줄인다. 사람 말은 그대로 둔다.
- 목표: 로봇이 말하는 중에 한 "멈춰"·"비카야"가 지금보다 잘(적어도 같게) 잡힌다.
- 하지 않는 것:
  - 스피커·배선 변경, 칩 설정 변경(칩 에코 제거·증폭 값은 그대로 둔다).
  - 지금 있는 2차 장치 제거(로봇이 말하는 중 표시, 자기 목소리 거름, "정지합니다" 동안 마이크 닫기, 받아쓴 글자 메아리 기각).
  - 문턱값 다시 맞추기(`listen_min_rms` 등) — 켠 뒤 따로 본다.
  - 칩 VAD·방향(USB 로 읽는 값)은 칩 안에서 나오므로 달라지지 않는다. 그 값을 쓰는 끼어들기 판정은 이 설계 밖이다.
  - 지연 자동 추정, 남은 에코를 더 깎는 뒤처리(시험에서 0.1 dB 차이뿐이었다).
  - 마이크 점검기(`tools/mic_venue_check.py`)에 넣기 — `on` 이 자리 잡은 뒤 따로 한다(4.5).
- 실패로 보는 것:
  - **"멈춰"가 한 번이라도 덜 잡히거나 늦어짐**(원칙: 긴급어는 절대 막지 않는다).
  - 사람 말이 깎이거나 찌그러져 호출·받아쓰기 결과가 나빠짐.
  - 마이크 처리 루프가 멈추거나 밀림(에코 제거가 죽어도 소리는 그대로 흘러야 한다).
  - 스위치가 `off` 인데 동작이 한 비트라도 달라짐.

  — 이 설계와 같은 방식이다.

## 4. 설계

### 4.1 흐름

```
reSpeaker 6ch 블록(80 ms, 1280 표본)
  ├─ ch1~4 → 경비 소리 판정(patrol_tap)            … 그대로
  └─ ch0 + ch5 ─→ [에코 제거] ─→ process_frame(…)  … 호출·긴급어·듣기 창·저장 소리 전부 이 뒤
```

- 새 모듈 `src/echo_cancel.py`. `libspeexdsp.so.1` 을 ctypes 로 부른다(`speex_echo_state_init`, `speex_echo_cancellation`,
  표본율 16000 설정). 값: speex 프레임 160 표본, 필터 길이 4096 표본(256 ms), 기준 신호 늦춤 1600 표본(100 ms).
  - 늦춤은 모듈 안의 지연 버퍼로 한다. 블록마다 ch5 를 넣고 100 ms 전 것을 꺼내 쓴다.
  - 한 블록(1280)을 프레임 8개로 나눠 차례로 처리하고, 같은 길이의 int16 을 돌려준다. 소리에 지연을 더하지 않는다.
- 넣는 곳은 `wakeword_monitor.run()` 한 곳이다. 지금 콜백은 `block[:, 0]` 만 큐에 넣는다. 이를 ch0·ch5 를 함께 넣게 바꾸고,
  감시 루프가 `process_frame` 을 부르기 직전에 에코 제거를 거친다.
  - 콜백 안에서 처리하지 않는다(소리 스레드는 가볍게 둔다).
  - **모든 블록을 빠짐없이 거친다.** 마이크가 닫힌 상태(`_is_muted`)·로봇이 말하는 중이어도 처리한다 — 그때 학습이 된다.
- 기준 신호가 조용할 때(로봇이 말하지 않을 때) speex 는 소리를 거의 그대로 내보낸다(실측 −0.05 dB, 비트까지 같지는 않다).
  로봇 말 여부를 따로 알려 주지 않는다.
- 스트림을 새로 열 때(음성 노드 시작)마다 처음부터 학습한다. 학습 결과를 파일로 남기지 않는다.

### 4.2 스위치 (`.env`)

- `VICA_SW_AEC=off|log|on`, 기본 `off`.
  - `off`: 모듈을 만들지 않는다. 큐에는 지금처럼 ch0 만 들어가도 된다. 동작은 지금과 완전히 같다.
  - `log`: 에코 제거를 돌리되 **결과를 쓰지 않는다**(모델·저장 소리는 원래 ch0). 줄임량만 기록한다(4.4).
  - `on`: 처리한 소리를 `process_frame` 에 넘긴다.
- `VICA_SW_AEC_DELAY_MS`(기본 100) · `VICA_SW_AEC_TAIL_MS`(기본 256). 값이 이상하면 기본값으로 돌고 경고 한 줄.
- 되돌리기: `.env` 에서 `off`(또는 줄 삭제) 뒤 음성 노드 재시작.

### 4.3 죽어도 소리는 흐른다

- 라이브러리를 못 찾거나 초기화에 실패하면: 경고 한 줄을 남기고 `off` 처럼 돈다. 음성 노드는 뜬다.
- 처리 중 예외가 나면: 그 블록은 원래 ch0 을 넘기고, 에코 제거를 그 실행 동안 끈다(경고 한 줄, 되살리지 않는다).
- 블록 길이가 1280 이 아니면(끊김 뒤 짧은 블록 등): 그 블록은 원래 ch0 을 넘기고 상태를 새로 만든다.

### 4.4 기록

- 로봇 말 한 덩어리(ch5 가 조용하지 않은 구간, 1 s 이상)가 끝날 때마다 한 줄: 시각 · 길이 · 처리 전 rms · 처리 뒤 rms · 줄임 dB · 모드.
  파일 `~/vica_data/aec_log/YYYYMMDD.jsonl`. 화면 로그에는 남기지 않는다(로봇이 자주 말한다).
- 건강 신호: 줄임량이 3 dB 미만인 덩어리(길이 3 s 이상)가 5번 이어지면 화면 로그에 경고 한 줄
  ("에코 제거가 듣지 않음 — 스피커 지연이 바뀌었을 수 있음"). 한 번 낸 뒤에는 회복될 때까지 다시 내지 않는다.
- `on` 일 때 `wake_clips`·`listen_clips`·긴급 소리 저장은 처리 뒤 소리다(모델이 들은 것). `clips.jsonl` 에 `aec` 칸(모드)을 더한다.

### 4.5 점검기 — 이번에는 넣지 않는다

- `tools/mic_venue_check.py` 는 자기 스트림에서 `block[:, 0]` 만 쓰고, 칩 값을 쓸 때마다 스트림을 닫았다 연다. 로봇 소리는 6단계에서만
  나므로 에코 제거를 넣으면 6단계가 매번 학습 0 에서 시작한다(첫 2~4 s 가 덜 지워진 채 `level` 평균에 들어감). 지난 점검과의 비교
  (`previous_robot_level`, 1.5배 경고)도 켠 점검·끈 점검이 섞이면 틀어진다.
- 그래서 이번 범위에서 뺀다. 점검기 6단계 값은 계속 **처리 전** 소리 기준이다(운영보다 로봇 소리가 크게 재어지는 쪽 — 안전한 방향).
- 운영에서의 효과는 `aec_log`(4.4)와 다시 틀기 도구(5절)로 본다.

## 5. 시험과 합격 기준

1. 단위 시험(가짜 신호, 라이브러리 없으면 건너뜀):
   - 기준 신호를 118 ms 늦춰 짧은 필터에 통과시킨 가짜 에코 → 5 s 뒤 줄임 6 dB 이상.
   - 기준이 조용할 때 출력이 입력과 1 dB 안에서 같다.
   - `off` 는 입력과 한 비트도 다르지 않다. `log` 는 넘기는 소리가 입력과 같다.
   - 라이브러리 없음·처리 예외·짧은 블록에서 원래 소리가 넘어가고 루프가 계속 돈다.
   - 감시기 연결: 닫힌 상태(`_is_muted`)에서도 에코 제거에 블록이 들어간다.
2. 다시 틀기 도구 `tools/aec_replay.py`: 6채널 wav 를 `off`·`on` 두 길로 통과시켜 견준다. 같은 녹음이라 말한 사람·크기 차이가 섞이지 않는다.
   - **판정은 운영 감시기 전체로 한다.** 점검기의 다시 채점(`src/mic_check_replay.py`)처럼 `WakewordMonitor` 에 블록을 차례로 넣고,
     녹음에 남긴 시각표대로 `note_robot_speech`·`set_speaking` 을 불러 준다. "잡힘" = 감시기가 낸 `emergency`·`wake` 사건이다.
     로봇 말 중 "멈춰"는 운영에서 관문(`GATE_B_SPEAKING` 0.35) → 말끝 0.32 s → 받아쓰기 확인을 거치는데, 확인이 듣는 직전 2.5 s 에
     로봇 소리가 섞여 있으므로 점수만 봐서는 실패 기준을 판정할 수 없다.
   - 칩 VAD·방향은 녹음에 없으므로 넣지 않는다(감시기는 없음으로 처리). 긴급어·호출 확정에는 쓰이지 않는다.
   - 곁들여 내는 것: 조각 점수 최고점, 받아쓴 글자, 로봇 구간 줄임 dB.
3. 녹음 묶음(사용자가 말해 주어야 함, 약 5분, 주행 끈 상태, `~/vica_data/mic_checks/20261118-aec/aec_probe.py` 를 넓혀 씀):
   - 로봇만 60 s(점검 멘트 8개 두 바퀴)
   - 사람만: "비카야 화장실 가자" 5회 · "멈춰" 5회
   - **로봇이 말하는 중에**: 멘트 하나에 한 번씩 "멈춰" 10회 · "비카야" 10회
   - 녹음 옆 json 에 남길 것: 멘트마다 재생 시작·끝 시각과 문장(감시기에 알려 줄 것), 사람 차례의 시작·끝 시각, 칩 값.
     **녹음은 한 번이므로 이 형식을 먼저 확정하고 녹음한다.**
4. 합격(숫자는 첫 결과를 보고 사용자와 확정한다 — 아래는 제안):
   - 로봇 말 중 "멈춰": `on` 의 `emergency` 사건 수 ≥ `off`(한 건도 줄지 않음). 같은 녹음에서 사건 시각이 `off` 보다 한 블록(80 ms)
     넘게 늦지 않음.
   - 로봇 말 중 "비카야": `on` 의 `wake` 사건 수 ≥ `off`.
   - 사람만: 사건·글자 결과가 같고 크기 변화 1 dB 안.
   - 로봇만: 줄임 중앙값 6 dB 이상(처음 4 s 제외), 로봇 말에 호출·긴급어 사건이 새로 생기지 않음.
5. 실기 순서: `log` 로 한 차례 운영 → `aec_log` 숫자 확인 → `on` → `aec_log` 숫자와 `wake_clips` 를 귀로 확인(로봇 말소리가
   줄었는지) → 평소 시나리오 1회. 단계마다 사용자 승인 뒤 넘어간다.

## 6. 한계와 위험

- 줄임은 약 9 dB(진폭 약 1/3)다. 로봇 소리가 완전히 사라지지 않는다. 지금 근거는 **녹음 한 개·한 장소**다.
- 겹쳐 말하기 근거는 합성 1건이다(ch0 끼리 더함 — 칩 증폭이 실제와 다를 수 있다). 5절 녹음으로 확인한다.
- 음성 노드를 켠 뒤 로봇 말 첫 2~4 s 는 덜 지워진다. reSpeaker USB 가 다시 잡혀 노드가 재시작되면 다시 학습한다.
- 스피커 지연이 100~356 ms 창을 벗어나면 듣지 않는다(4.4 건강 신호로 알린다). 지금 118~122 ms.
- 호출 모델 v2 는 처리 전 소리로 학습됐다. 사람 말은 −0.1~−0.5 dB 변화라 영향이 작다고 보지만 5절에서 확인한다.
- 로봇 말이 작아지면 자기 목소리 거름·메아리 기각이 걸리는 횟수가 달라질 수 있다(줄어드는 방향).
- 점검기 6단계는 처리 전 소리로 잰다(4.5). `on` 뒤에는 점검기 값이 운영보다 로봇 소리를 크게 본다.

## 7. 내가 정한 것 (확인 부탁)

- **작업 자리**: 음성 노드는 운영 작업 폴더(`vica-voice-llm`, `after_feedback_waiting`)에서 바로 돈다. 고치는 도중의 코드가 음성 노드
  재시작에 딸려 들어가지 않게, 따로 떼어 낸 작업 폴더 `~/wt-aec-voice`(브랜치 `feat/sw-aec`)에서 만들고 시험·다시 틀기 합격 뒤
  운영 브랜치에 합친다. 푸시하지 않는다. (새 브랜치를 만드는 일이라 승인이 필요하다.)
- 스위치 3단(`off|log|on`)과 기본 `off` — 호출 후보 설계(11-18)의 "먼저 기록만" 방식을 따랐다.
- 판정은 운영 감시기 전체로(5.2), "늦어짐"은 같은 녹음에서 `off` 대비 사건 시각으로 잰다.
- 점검기는 이번 범위에서 뺀다(4.5).
- 기록 파일 위치 `~/vica_data/aec_log/`, 건강 신호 기준(3 dB·3 s·5번).
