# 3-나-1 — 오프라인(글자 경로) 일시정지·재개 오독 수리 (짧은 설계)

작성 2026-11-18. 바탕 설계 `2026-11-14-question-aware-answers-design.md` 7절의 3-나를 둘로 나눈 앞부분(사용자 11-18
"3-나-1부터"). 뒷부분 3-나-2 = 그 설계의 4.2·4.3·4.6(LLM 출력 형식을 바꿈). 실기·측정 자료 `~/vica_data/field_test_20261118/`.

## 1. 왜

11-18 오프라인 실기(글자 경로 · 로컬 midm2-mini)에서 주행 중 "네 잠깐만."과 일시정지 중 "네. 다시 가자."·"다시 출발."·
"다시 가자."가 4번 모두 **407호(비공개) 이동**으로 읽혔고, 첫 거절 때 일시정지해 둔 안내가 사라졌다(13:15:23~13:16:26).
받아쓰기는 정확했다. 사용자 11-18: "3-가의 오프라인은 좀 심각하다."

**측정(11-18, `hist_replay.py`)**: 실기 발화 74개(오프라인 50 + 온라인 24)를 그때의 대화 기록·미션 상태로 되살려 로컬
LLM 에 다시 넣었다. 되살린 입력은 어림이다(LLM 을 부른 오프라인 발화 33개 중 21개만 실제 결과와 같음) — 후보끼리의 비교에 쓴다.

  navigate 설명) 바꾸기 — 6절.

## 2. 목표 · 하지 않는 것 · 실패로 보는 것

- 목표: 글자 경로에서 일시정지·재개 말을 LLM 없이 규칙으로 읽는다. 로봇의 "네?"가 섞인 글자를 정리한다. 일시정지 중의
  거절이 일시정지를 풀지 않는다.
- 하지 않는 것: 대화 기록 줄 수·내용 바꾸기(측정상 효과 없음) · "어디야"류 질문 해석(3-나-2) · 듣기 창을 "네?" 뒤에
  열기(바탕 설계 4단계) · LLM 출력 형식 · 소리 경로(Realtime)의 판단 · 새 멘트.
- 실패로 보는 것: 확인 없이 출발하는 길이 생김 · 온라인 주 경로(Realtime) 동작이 달라짐 · "잠깐"·"멈춰"가 늦어짐.

| 방법 | 장점 | 한계 | 결정 |
|---|---|---|---|
| 기록 줄이기·고르기 | 수정이 작음 | 측정: 잘못된 행동 14 → 15~17 | 버림 |
| LLM 이 낸 목적지가 사용자 글자에 없으면 버리기 | 결정적 | "배 아파 → 화장실" 짐작 안내를 막음 | 버림 |
| **일시정지·재개 말은 글자 규칙, "네?" 메아리는 글자에서 떼기, 미션 일시정지 유지** | LLM 을 거치지 않아 0초·같은 입력에 같은 결과(F4) | 규칙에 없는 말은 지금처럼 LLM | **채택(사용자 11-18)** |

## 4. 설계

### 4.1 호출 응답 메아리 떼기 (음성)
- 원인: 호출이 확정되면 듣기 창이 바로 열리고 같은 순간 미션의 "네?"가 재생된다(13:15:19.50 · 19.52). 로봇 목소리가
  녹음에 들어가 "네 잠깐만."으로 받아써진다. 22일 자료에서 "네?" 뒤 378건 중 36건(9.5 %)이 "네"로 시작한다.
- 규칙: 발화 때 열린 질문 기록이 `kind=open` 이고 글자가 "네?"(`WAKE_GREETING`)이면, 사용자 글자 맨 앞의 "네" 한 낱말과
  뒤따르는 문장부호(`.` `,` `?` `!`)를 뗀다. **뒤에 말이 남을 때만.** "네." 한마디는 그대로 둔다.
- 뗀 글자를 글자 규칙·LLM·대화 기록에 쓴다. 로그에 "앞 '네' 뗌: 원문 → 결과" 한 줄. 화자 판정(`SpeakerLink`)은 호출어
  노드가 낸 원문 글자로 맞추므로 원문으로 찾는다 — 뗀 글자로 찾으면 판정이 끊긴다.
- 근거: "네?"는 네/아니요 질문이 아니라서, 사용자가 실제로 "네, 화장실 가자"라고 했어도 "네"를 떼어 뜻이 달라지지 않는다.
- 글자 경로에만 건다(오프라인, 그리고 온라인에서 Realtime 이 실패해 글자 경로로 넘어간 발화). 순수 함수로 두고 ROS 없이 시험한다.

### 4.2 일시정지·재개 글자 규칙 (음성, `_shortcut_intent`)
- `_PAUSE_WORDS` 에 "잠깐"·"잠시"를 더한다(지금은 잠깐만·잠깐만요·잠시만·잠시만요). 11-18 13:15:37 "잠깐."은 LLM 이 1.8 s 걸려 읽었다.
- 재개 낱말(정규화 뒤 통째 일치): 다시 가자 · 다시 가 · 다시 가줘 · 다시 출발 · 다시 출발해 · 다시 출발해줘 · 다시 출발하자 ·
  출발 · 출발해 · 출발해줘 · 출발하자 · 계속 가자 · 계속 가 · 계속 가줘(+ "요" 붙은 꼴). 미션의 대화 단계가 `paused` 일 때만.
- 결과는 LLM 이 낼 때와 같은 꼴 — `resume` · `need_confirm=True` · `reply=RESUME_CONFIRM`. 뒤 흐름("다시 출발할까요?" →
  "네" → 출발, 침묵이면 한 번 다시)은 그대로다. **확인을 건너뛰지 않는다.**
- 손 놓침으로 선 일시정지(`paused_handle`)에는 걸지 않는다 — 그 재개는 손잡이를 다시 잡는 것이다.
- 대화 단계는 `parse_intent` 가 로컬 규칙(`VICA_LOCAL_RULES=1`·글자 입력)일 때만 넘긴다. 그래서 재개 규칙은 오프라인 실행에서만
  걸린다(온라인의 글자 폴백은 지금 그대로). "다시 출발할까요?"가 이미 열려 있을 때의 재개 낱말은 승낙으로 읽는다 — LLM 이
  resume 을 낼 때의 기존 동작(`_finalize` 의 `pending_command`)과 같다.
- 근거의 한계: 22일 자료에 재개 발화는 2건뿐이다. 낱말은 11-18 실기와 미션 안내("다시 출발하려면 말씀해 주세요")에서 뽑았다.
  받아쓰기가 깨진 꼴("다시 가져"·"다 지출 발")은 넣지 않는다 — 지금처럼 LLM 몫.

### 4.3 일시정지 중 거절은 일시정지를 둔다 (미션)
- `mission_logic.on_intent` 의 확정 요청 거절 갈래는 대기 상태가 아니면 `_to_idle()` 을 부른다. 일시정지 중이면 보관하던
  목적지가 사라진다(13:15:52 `paused -> idle`, 그 뒤 "다시 가자"는 "다시 출발할 안내가 없습니다").
- 고침: 일시정지(`State.PAUSED`) 중 거절은 상태를 그대로 둔다(대기 상태와 같은 취급). 거절 멘트는 지금 그대로 말한다.
- 반응 규칙 시험(`test_reaction_rules.py`)에 더한다(반응표의 열은 갈 수 있는 곳만 쓴다). 미션 빌드·재시작이 필요하다(그때 사용자에게 묻는다).

## 5. 확인

- 음성·미션 시험 통과(미션 기준 실패 5개는 그대로).
- 같은 74발화 재생: "다시 가자"류 중 일시정지 상태인 것과 "잠깐"류가 규칙으로 처리된다. 대입 계산으로는 잘못된 행동
  14 → 9 — 일시정지 중 재개 2건(4.2) · 4.3 으로 일시정지가 남아 규칙에 걸리는 2건 · "다시 출발할까요?" 고정 문장
  (719a5e0, 이미 넣음)으로 풀리는 "그래" 1건. 실측이 아니라 계산이다 — 로봇이 빌 때 다시 잰다.
- 208행 재생(Mi:dm): 잘못된 행동이 14 를 넘지 않는다(로봇이 빌 때).
- 실기(오프라인): 주행 중 "비카야" → "잠깐" → 일시정지 → "비카야" → "다시 가자" → "다시 출발할까요?" → "네" → 출발.
  일시정지 중 갈 수 없는 곳 요청 → 거절 멘트 뒤에도 "다시 가자"가 통한다.

## 6. 따로 재서 정할 것 (이 설계에 넣지 않음)

- 지시문 예시: 글자 경로 지시문의 navigate 설명에 `직접 표현("407호 가자")`가 있고, vica_map_0630 목록에 407호(접근 불가)가
  있다. "다시 가자"가 "407호 가자"와 꼴이 같아 로컬 LLM 이 407호를 고르는 것으로 보인다(가설). 예시를 목록에 없는
  꼴로 바꿔 같은 74발화를 재생하면 10분에 확인된다.
- 지시문 규칙 추가("말에 장소가 없으면 navigate 를 고르지 않는다")도 같이 잰다.
- 효과가 있으면 3-나-1 에 덧붙이고, 없으면 "어디야"류와 함께 3-나-2 에서 다룬다.

## 7. 빌더에게 맡기는 것

- 떼기 함수의 자리(새 순수 모듈 또는 `local_rules`)와 `ros_node` 에서 부르는 자리, 로그 문구.
- 재개 낱말 목록의 세부(위 목록은 반드시 덮는다)와 정규화(`handle_mode.normalize_short_reply`).
