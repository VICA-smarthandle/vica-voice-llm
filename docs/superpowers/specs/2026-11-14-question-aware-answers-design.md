# 질문을 아는 대답 해석 — 음성 에이전트 1단계 설계

작성 2026-11-14. 결정 기록: 11-13·11-14 대화(사용자 = 음성·LLM 담당).
조사 자료: `~/vica_data/voice_answer_audit_20261113/` (README.md · qa_all.csv 1,660건 · qa_flagged.csv · extract_qa.py · flag_qa.py).
이어지는 설계: `2026-11-11-speaker-follow-design.md`(화자 판정). 이 설계의 11-11 임시 수리(`identity_answer`·`spk_gate_question`,
커밋 ebd40c0)는 4절 구조로 대체된다.

## 1. 왜

**증상.** 로봇이 정해 둔 길(질문 → 예상한 대답)에서 벗어난 대답이 오면 바로 꼬인다. 10-10~11-11 실기 22일 로그에서
로봇 질문 뒤 40 s 안의 사용자 말 1,660건을 뽑아 의심 206건을 읽은 결과:

| # | 유형 | 건수 | 실제 예 |
|---|---|---|---|
| 1 | 네/아니요를 질문 형태와 다르게 읽음 | 12 | 11-06 11:32 "여기까지 안내를 마칠까요?" → "아니" → `cancel` → 안내 종료(정반대) |
| 2 | 숫자 대답을 다른 의도로 | 7 | 10-12 16:59 "몇 분쯤 걸리실까요?" → "십 분" → `navigate` 비공개 목적지 |
| 3 | "아니 + 다른 곳"을 못 받음 | 5 | 10-21 10:38 "기다릴까요?" → "아니 사회복지창고로 가자" → 침묵 |
| 4 | 대답 자리에 "비카야" | 22 | 10-24 12:14 확인 질문 → "비카야" → "네?" → 다시 요청 → 확인 질문… 4번 |
| 5 | 질문 전에 시작한 대답을 조용히 버림 | 3 | 11-04 11:04 "마칠까요?" → "아니." 무시 |
| 6 | 사람끼리 하는 말이 대답 자리에 | 약 20 | 11-11 21:27 "이 뒤로는 잘 안 넘어가네" → LLM "어디 부분에서 막혔는지요?" |
| 7 | 두 목소리(LLM 확인 질문 + 미션 출발) | 4 | 11-06 15:30 "…로 안내해드릴까요?" 직후 "안내를 시작합니다" |

**원인.**
- 대답을 읽는 쪽(LLM)이 로봇이 방금 무엇을 물었고 어떤 대답을 기다리는지 데이터로 모른다. `schema.py` 의
  `VicaIntentType` 주석이 그대로다: "어느 질문의 답인지는 담지 않는다 — Mission 이 상태로 판정한다."
  LLM 은 `dialog_state` 와 마지막 로봇 말의 글자로 짐작한다.
- 말할지 정하는 곳이 두 군데(미션·음성 노드)다. 겹침은 `mission_question.quiet_for_mission` 에 예외를 덧대 막아
  왔고, 덧대지 않은 자리에서 다시 꼬였다(11-11 본인 질문 버그 2개가 그 예).

## 2. 목표 · 하지 않는 것 · 실패로 보는 것

**목표**
- G1. 로봇이 묻는 모든 질문을 데이터(질문 기록)로 내고, 대답은 그 질문의 범위 안에서 읽는다.
- G2. 예상 밖 대답(덧붙인 말, 말로 한 숫자, 마음 바꿈, "비카야", 딴말)에도 꼬이지 않는다. 정말 모르면 정해진 3단계로
  되묻는다.
- G3. 한 번에 한 목소리. 질문이 열려 있는 동안 다른 쪽은 말하지 않는다.
- G4. 폐쇄망에서 Jetson 안의 모델만으로 같은 기능이 돈다(로컬 = KT Mi:dm 2.0 Mini).
- G5. 해석 경로는 관리자가 `.env` 로 고른다.
- G6. 1,660건에서 뽑은 시험 묶음으로 "잘못된 행동 0건"을 잰다.

**하지 않는 것 (이번 단계)**
- LLM 도구(건물 안내·상태 묻기·관리자 호출 등) — 11-14 사용자: 무엇을 만들지 더 생각한다. 다음 단계.
- 자동 경로 전환(인터넷 유무로 고르기) — 11-14 사용자: `.env` 로 관리자가 정한다. 단 아래 D4 의 연결 오류 시 로컬
  전환은 남긴다.
- 겹친 말 분리, XVF3800.

**실패로 보는 것 (만들어져도 실패)**
- F1. 반응이 지금보다 눈에 띄게 느려짐. 지금 대답 → 반응: Realtime 1.0~2.5 s(11-11 로그 `dt`), Mi:dm 평균 2.1 s ·
  p90 2.6 s(09-28 스택 bench).
- F2. 로봇 말이 많아짐(10-09 "짧고 차분하게", 멘트 최소주의).
- F3. 안전 경로 우회: LLM 이 미션 승인 없이 움직이게 하거나 "멈춰" 가 조금이라도 늦어짐. 긴급어 경로는 손대지 않는다.
- F4. 같은 입력에 매번 다른 반응(시험·재현 불가).
- F5. 오프라인(Mi:dm)에서 기능이 줄어듦.
- F6. 새 ROS 노드 추가(선승인 규칙). 새 토픽·메시지는 된다.

## 4. 구조

### 4.1 질문 기록 (미션 → 음성)

미션은 대답을 기다리는 말을 낼 때마다(`Say.expects_reply=True` 인 모든 자리) 질문 기록을 함께 낸다. 질문이 닫히면
(대답을 받음·대답 없이 듣기가 끝남·상태 바뀜) 빈 기록을 낸다. 닫는 기준에 시간을 쓰지 않는다 — 음성의 듣기 결과
(`/vica/listen_state` 의 `empty…`)를 본다(11-17 사용자: 40 s 는 근거 없음. 실기 대답은 99 % 가 17.5 s 안, 최대 23.6 s).

- 토픽 `/vica/question`, 새 메시지 `vica_interfaces/msg/VicaQuestion.msg`, TRANSIENT_LOCAL depth 1.
- 칸: `id`(질문마다 새 값) · `kind`(아래 표) · `text`(로봇이 말한 문장 그대로) · `options`(고르기·확인의 목적지 id/name 목록)
  · `step`(되묻기 단계 0~3) · `on_silence`(무응답 끝의 기본 동작 이름) · `opened_at`.

질문 종류와 받는 대답(조사 1,660건의 질문을 다 덮는다):

| kind | 예 | 받는 대답 |
|---|---|---|
| `open` | "네?", "어디로 가고 싶으신가요?" | 명령·목적지·질문 |
| `confirm` | "사회복지로 안내해드릴까요?" | 네 / 아니요 / 다른 목적지(C3) |
| `choice` | "남자 화장실과 여자 화장실 중 어디로 갈까요?" | `options` 중 하나 / 아니요 |
| `yesno` | "여기서 대기할까요?", "여기까지 안내를 마칠까요?", "안내를 받으시겠어요?", "안내를 취소할까요?", "직원의 도움이 필요하신가요?", 본인 질문 | 네 / 아니요 (+ 다른 목적지는 C3) |
| `yesno_inverted` | "안내가 필요 없으신가요?" | 네 = 필요 없음 / 아니요 = 필요함 |
| `minutes` | "몇 분쯤 걸리실까요?" | 분(말로 한 숫자 포함) / 아니요 |

### 4.2 대답 (음성 → 미션)

`VicaIntent` 끝에 칸을 덧붙인다(옛 소비자 호환, 11-11 `speaker_*` 와 같은 방식).

- `question_id`: 읽을 때 기준으로 쓴 질문 기록 id. 열린 질문이 없으면 "".
- `answer`: `yes` · `no` · `destination` · `choice` · `minutes` · `repeat`("비카야"만) · `other`(질문에 맞지 않는 명령·질문, C5 —
  `intent` 칸으로 처리) · `not_for_robot` · `unclear` · ""(질문 없음).
- `answer_value`: 목적지 id · 고른 항목 · 분.
- `addressed`: `yes` · `no` · `unsure`(LLM 판정, 4.3 e).
- `ask_text` · `ask_kind` · `ask_options`: LLM 이 되묻고 싶을 때(지금의 `clarify`) 지은 문장(4.6 을 거친 뒤)과 그 질문의
  kind·후보. 미션이 이 문장을 말하고 같은 내용의 질문 기록을 낸다(C2·D10).

미션은 `question_id` 가 지금 열린 질문과 같을 때만 `answer` 로 처리한다. 다르면(늦게 온 옛 대답) 되묻기 ①(C4).
`intent` 칸은 남겨 열린 질문이 없을 때의 지금 흐름을 그대로 둔다.

### 4.3 해석 순서 (음성 노드, 열린 질문이 있을 때)

a. **긴급어 먼저** — 지금 경로 그대로(`emergency_filter`, 호출 노드 모델 B). 이 설계는 손대지 않는다.
b. **"비카야" 단독** → `repeat`(D6). "비카야 + 말"은 "비카야"를 떼고 c 로.
c. **글자 규칙(LLM 없이, 바로)** — 질문 kind 에 맞는 것만 본다.
   - 네/아니요: `handle_mode.AFFIRMATIVES`·`NEGATIVES`. 첫 낱말이 부정이고 뒤에 목적지가 있으면 C3.
   - 분: 한글 숫자("십 분", "한 오 분", "반 시간", "삼십 분") → 정수.
   - 목적지·고르기: 목적지 name·별칭이 하나로만 맞을 때.
   - 확실할 때만 답한다. 아니면 d 로.
   - 소리 경로가 주력이면(D11) 받아쓴 글자가 정확히 짧은 네/아니요이거나 "N분"일 때만 이 규칙의 답을 쓰고 Realtime
     결과는 기록만 한다. 목적지·고르기는 Realtime 결과를 쓴다. 받아쓰기 0.3~0.7 s · Realtime 1.0~2.7 s(11-11 로그).
d. **LLM** — `.env` 로 고른 경로(D4). 출력은 질문 kind 로 좁힌 형식(가능한 `answer` 값만 열거) + `addressed`.
   - Mi:dm: Ollama 구조화 출력(지금 `ChatOllama.with_structured_output` 과 같은 길), 질문 kind 별 JSON 스키마.
   - Realtime: 지금 강제 도구 `set_intent` 의 매개변수에 같은 칸을 더하고, 턴마다 질문 문장·kind 를 지시문에 넣는다.
   - gpt-5.4-mini: Mi:dm 과 같은 스키마.
e. **수신자 판정(D7·C7)** — 소리 쪽 "아님"(11-11 거르기 조건)인 말은 호출 노드가 이미 조용히 버려 여기까지 오지
   않는다. 여기 온 말은 뜻 쪽만 본다: `addressed=no` → `unclear`(되묻기 ①), `addressed=unsure` → c·d 의 결과를 그대로
   쓴다. 둘 다 "아님"인 말이 `not_for_robot` 이 되는 자리는 화자 판정이 소리 쪽을 "애매"로 넘긴 경우(짧은 말 방향
   경계 등)다 — 빌더가 11-11 판정 출력에서 이 경계를 정한다.

### 4.4 한 목소리

- 질문 기록이 열려 있는 동안 음성 노드는 TTS 를 보내지 않는다(긴급 처리는 별개, 지금 그대로).
- 확인 질문·고르기 질문·LLM 의 되묻기도 미션이 말한다(C2). LLM 이 `navigate`(목적지 하나)를 내면 미션이 목적지의
  `confirm_prompt` 로 묻고, LLM 이 `ask_text` 를 내면 미션이 그 문장을 그대로 말한다. 어느 쪽이든 미션이 질문 기록을 낸다.
- LLM 이 소리 내 답하는 것은 사용자가 먼저 꺼낸 질문(`question`)뿐이다. 질문이 열려 있을 때는 C5 대로 미션이 질문을
  잠시 놓고(대답 대기 시계 멈춤), LLM 답이 끝나면(`/vica/tts_done`) 다시 들려준다.
- 이로써 `quiet_for_mission` 의 예외 목록과 11-11 임시 수리는 필요 없어진다. 지울 때 기존 시험이 지키던 동작(취소·
  도움·접근 질문 중 두 목소리 없음)은 새 시험으로 옮긴다.
- 3-가 결정(11-17 사용자): A 확인 질문은 미션 `confirm_prompt` 문장(LLM 문장 버림) · B "다시 출발할까요?"는 말만
  미션, 보류·다시 묻기 판단은 음성에 둠(C8 은 3-나) · D 미션이 받지 않는 상태의 제안은 확정 요청과 같은 거절
  (다가가는 중·찾는 중 `MSG_APPROACH_BUSY`, 관리자 주행 `MSG_BUSY`, 관리자가 오는 중 `MSG_HELP_COMING`) — 10-07
  '제안 단계 침묵'은 음성이 이미 물어서였다. 계획서 `plans/2026-11-17-one-voice.md`.
- 확인 없이 나온 '확정'은 제안으로 낮춘다(사용자 11-18): 음성은 navigate 확정을 그 목적지의 확인 질문(질문 기록
  `confirm`, 후보에 그 목적지)이 열려 있을 때만 그대로 보낸다. 아니면 제안으로 낮춰 미션이 확인 질문을 한다. 갈 수 없는
  곳은 그대로 보내 미션이 이유를 말한다(`one_voice.demote_unasked_confirm`). 근거: 11-18 실기 13:05:39 — 두 번 거절한
  뒤의 "화장실로 가자"에 LLM 이 확정을 내 확인 없이 출발. 질문 기록을 판단에 쓰는 첫 자리다.

### 4.5 되묻기 (미션, 질문 하나마다)

미션은 지금 질문마다 흩어진 다시 묻기 표시(`_confirm_reasked`·`_cancel_reasked`·`_wait_*_reasked`·
`APPROACH_REASK_MAX` 등)를 질문 기록 하나의 `step` 으로 합친다.

| 받은 것 | 동작 | 셈 |
|---|---|---|
| 맞는 `answer` | 그 질문의 동작, 질문 닫음 | — |
| `repeat`("비카야"만, D6) | 질문 문장 + 대답하는 법 한 문장 다시. 예: "사회복지로 안내해드릴까요? 네 또는 아니요로 말씀해 주세요." | 안 셈 |
| `not_for_robot` | 아무 말 없이 질문 유지 | 안 셈 |
| `unclear` · 늦은 대답 · 무응답(질문마다 지금 기다리는 시간) | `step` +1 후 그 단계 말 | 셈 |

- ① "잘 듣지 못했습니다. 다시 말씀해 주세요."(`replies.RETRY_PROMPT`, 있는 멘트)
- ② 실제로 나올 자리(조사): 같은 질문에 연달아 두 번 못 알아들은 경우는 22일 6건뿐이고, 새 구조에선 6건 모두
  ②까지 가지 않는다(딴말 4 → 무시, "그래" 1 → 글자 규칙, 되물음 1 → C5). 남는 것은 작은 소리(먼 대답·시끄러운 곳),
  계속 깨지는 받아쓰기, 망설임이다.
- ② "죄송합니다. 더 크게, 또박또박 말씀해 주세요." — 원인과 상관없이 하나(11-14 사용자: 사람들은 기계가 이렇게 말하면
  그대로 따른다). 소리 크기로 원인을 고르지 않는다.
- **대답하는 법 한 문장**(`repeat` 에서만, D6): `yesno` "네 또는 아니요로 말씀해 주세요." · `minutes` "5분, 10분처럼 말씀해
  주세요." · `choice` "{후보} 중에서 말씀해 주세요." · `open` "가실 곳 이름을 말씀해 주세요."
- ③ "직원의 도움이 필요하신가요?"(`MSG_HELP_CONFIRM`, 있는 멘트) → 네 = 관리자 호출(10-16 기능) / 그 밖 = `on_silence`.
  `on_silence` 는 움직이지 않는 쪽: 확인·고르기 = 출발 안 함, 도착 질문 = 그 자리 대기, 대기 중 질문 = 대기 유지.
- 접근 질문("안내를 받으시겠어요?")의 ③은 지금의 물러남(`MSG_APPROACH_UNANSWERED`)을 그대로 쓴다 — 아직 사용자가
  아닌 사람에게 직원 호출을 묻지 않는다(Claude 판단).
- 호출 응답 "네?"의 무응답은 셈하지 않고 조용히 닫는다(C6). 대기 중 본인 확인 흐름은 이 표를 쓰지 않는다(C7).
- 새 멘트 다섯 개(② 한 문장 + 대답하는 법 네 문장)는 멘트 최소주의 규칙상 **사용자 승인 뒤** 넣는다. ② 문장은 11-14
  사용자가 정한 것이다.

### 4.6 LLM 문장 말투 다듬기 (D10)

LLM 이 지은 문장(`ask_text`, 사용자 질문의 답)은 TTS 로 가기 전에 세 겹을 지난다.

1. **지시문** — 말투 규칙과 좋은 예·나쁜 예. 끝맺음은 미션 멘트와 같은 꼴("~할까요?"·"~인가요?"·"~말씀해 주세요."),
   한 문장, 짧게, 한국어만. 10-09 "짧고 차분하게" 규칙은 그대로.
2. **끝맺음 글자 규칙** — LLM 을 다시 부르지 않고 바로 고친다(지연 없음). 예: "~시는지요?" → "~시나요?",
   "~해 주세요?" → "~해 주세요.". 규칙 목록은 조사 130건의 어색한 문장(README 의 clarify 목록)에서 시작한다.
3. **깨진 문장만 대체** — 규칙으로 못 고치는 것(한국어 아닌 글자가 섞임, 길이 상한 초과)만 그 kind 의 정해진 문장으로
   바꾼다(`open` = "어디로 안내해드릴까요?", `choice` = 고르기 문장, 그 밖 = 되묻기 ①). 길이 상한은 빌더가 조사 자료로 정한다.

고친 문장은 로그에 "고치기 전 → 고친 뒤"로 남긴다. 실기에서 새 어색한 말투를 찾아 규칙을 늘리기 위해서다.

### 4.7 경로 선택 `.env`

- `VICA_INTERPRETER=realtime|midm|gpt` — 주력. 지금의 `VICA_INTENT_INPUT`·`VICA_LLM_PROVIDER`·`VICA_LLM_FALLBACK_MODEL`
  조합을 대신한다. 새 키가 없으면 옛 키로 지금처럼 동작한다(이행기).
- `VICA_INTERPRETER_SHADOW=off|realtime|midm|gpt` — 비교 기록. 결과는 로그(`[A/B]` 줄 확장)와 기록 파일에만.
- 키 이름은 Claude 판단.
