## 5. 어떻게 동작하나

### 5.1 장면 묶기

장면 = 한 번의 "사용자 차례". 시작은 호출 확정(`비카야 호출 #N`) 또는 질문 열림(`[질문] 열림 id`·`질문 예약`), 끝은 다음 장면 시작 직전.
그 안에 청취 창 결과 → 받아쓰기(user_text·user_audio) → 화자 판정 → LLM 판정 → 미션 음성 요청·질문 id → TTS 재생을 시각 순서로 담는다.
- 질문 id 가 붙는 줄은 미션 `[질문] 열림·닫힘`과 LLM `[질문] id=` 뿐이다(11-17~). 미션 `음성 요청 intent=…` 줄과 TTS `재생[…]` 줄에는
  id·출처가 없으므로 시각과 글자 맞춤으로 잇는다. 미션이 직접 한 말은 미션 노드의 `TTS[우선순위]: 말` 줄로 출처를 확정한다
  (mission_manager_node.py:2561 — 미션 자기 Say 만 이 형식).
- 11-17 이전 로그(행사 11-04~07)는 질문 id 가 없어 시각 근접으로 잇는다 — 화면에 "추정 연결" 표시.
- 질문 닫힘 사유는 answer·silence 말고도 replaced·state·no_signal 이 있다(11-17 이후 로그).

### 5.2 설계상 대답

**11-20 사용자 결정: "대답은 봐야 한다. 이런 상황에서 LLM 은 이런 대답을 할 것이라고 추측해서 적어 달라."**
그래서 설계상 대답은 두 칸으로 보인다 — ① 의도(누가 정했나: 규칙 / LLM 추정) ② 예상 로봇 문장.
- 같은 입력(받아쓴 글자, 그때의 dialog_state, 직전 로봇 말)을 **지금 코드**에 다시 넣는다. dialog_state 는 미션 상태 전이 줄로 만든 시계열에서 읽는다.
- 규칙(로컬 규칙·지름길·질문 대답 규칙)이 정하면 그 결과를 "설계상"으로 쓴다. `tools/answer_replay.py` 의 기계를 쓴다.
- LLM 을 거치는 말은 **LLM 에 다시 물어** 그 의도·reply 를 "LLM 추정 — 다시 물은 결과, 그때와 다를 수 있음"으로 쓴다.
  그때와 같은 경로로 묻는다(글자 경로면 그때 모델 midm·gpt, 소리 경로면 저장 클립으로 Realtime). 사람이 장면에서 버튼을 누를 때만
  묻고(목록 전체 "모두 다시 묻기"도 둔다), 결과는 캐시한다. 주행 묶음이 켜져 있으면 로컬 midm 재실행은 막는다(GPU 공유).
  외부 API 는 장면당 1번 — 버튼 옆에 경로를 적어 비용이 드는 걸 보이게 한다.
- 예상 로봇 문장은 미션 로직을 돌리지 않고 **의도 → 문장 표**로 만든다: 목적지 확인은 그 지도 destinations 의 `confirm_prompt`,
  미션 고정 문장은 `src/mission_phrases.py`(미션 MSG_* 의 사본, tests/test_mission_phrases.py 가 미션 파일과 글자 대조) — 표에 없는
  미션 문장은 같은 방식으로 사본을 늘린다. LLM 이 문장을 만드는 의도(clarify·question 등)는 LLM reply 를 그대로 쓴다. 이 칸은 늘 "추정" 표시.
- 주의(검토 확인): 지름길(`_shortcut_intent`)은 짧은 대답·취소·멈춤·재개·호출어만 처리하고 목적지 요청은 전부 LLM 으로 간다.
  소리 모드(`audio`)는 지름길을 쓰지 않는다. `answer_replay` 는 노드 후처리(재청취 기각·quiet_for_mission)와 미션 반응을 재현하지
  않는다(tools/answer_replay.py:229) — 재청취 기각처럼 노드 후처리가 낸 결과는 다시 넣기가 아니라 로그 사실로 보인다.

### 5.4 2단계 구조화 기록 (음성 노드만)

- 위치 `~/vica_data/voice_trace/<YYYYMMDD>/<노드>.jsonl`, 한 줄 = `{t, node, stage, decision, reason, values}`.
- 호출 노드: 호출 확정·놓침마다 최고점·**문턱 넘은 조각 수·연속 최대**·쿨다운 막힘·자기 말 보호 여부.
  청취 창 열림·닫힘마다 결과·창 안 최대 rms·**창 열린 직후 0.5 s 배경 rms**·화자 판정.
- 의도 노드: 입력 출처(글자·소리)·의도·재청취 기각 여부와 사유·질문 id.
- TTS 노드: 재생 시작·끝·끊김, 우선순위, 대기열 대기 시간.
- 소리: 호출 놓침은 이미 `~/vica_data/wake_clips` 에 저장되고 있다(11-17~) — 추가하지 않는다.
- **빈손 창은 소리 없이 숫자만** 남긴다(11-20 사용자 결정) — 듣기 루프에 버퍼를 더 두지 않는다. 대신 **"말소리 안 잡힘"을 명시**한다:
  자유 창·질문 창 모두 닫힐 때 노드 로그 한 줄 `청취 창 말소리 없음(자유 창|질문 창) — 창 안 최대 rms …·배경 rms …` 과 같은 내용의
  기록 줄을 남긴다(지금은 질문 창이 무음으로 닫히면 호출 노드에 아무 줄도 없다 — ros_wakeword_node.py:446). 화면에도 같은 문구로 보인다.
- 토픽·메시지 형식은 바꾸지 않는다(다른 구독자가 있다) — 노드끼리는 시각과 질문 id 로 뒤에서 잇는다.
- 스위치 `VICA_TRACE`(on/off). 끄면 지금과 똑같다.

### 5.5 화면

## 8. 내가 정한 것 (사용자 확인 대상)

- 새 ROS 노드 없이 오프라인 웹 서버 · 포트 8772 · 기본 127.0.0.1.
- `field_report.py` 는 그대로 두고 해석 규칙을 저장소로 옮겨 시험을 붙인다.
- LLM 다시 묻기는 사람이 버튼을 누를 때만, 그때와 같은 경로로, 결과 캐시. 주행 중에는 로컬 midm 재실행을 막는다.
- 예상 로봇 문장은 미션 로직을 돌리지 않고 의도 → 문장 표(confirm_prompt + mission_phrases 사본)로 만든다.
- `VICA_TRACE` 기본값 on — 기록만 하고 동작은 그대로라서(listen_clips 기본 켬과 같은 판단). 디스크는 하루 수 MB 예상(미측정).
- 시연자 말 판정은 자동으로 하지 않는다.
- LLM 실패 원인을 보려고 journal(`vica-llm.service`)과 relaunch 출력도 읽는다(없으면 시간 간격으로 추정 표시).
- 겹침은 출처와 상관없이 요청 시각 기준, 한 동작의 연속(0.1 s 미만)은 뺀다.
