# 이어 말한 호출 받기 — 호출 후보 2단계 확인 (짧은 설계)

작성 2026-11-18. 결정 기록: 11-17·11-18 대화(사용자 = 음성·LLM 담당). 재학습(v2)은 호출어 세션이 따로 한다
(`~/vica_data/wakeword_v2_20261117/PLAN.md`). 측정 자료 `~/vica_data/wake_near_review_20261118/README.md`.

## 1. 왜

사용자 관찰(11-17): 대부분의 사용자는 "비카야" → "네?" → 말이 아니라 "비카야 나 ㅇㅇ 가고 싶어"를 쉬지 않고 말한다.

측정(11-18, 로봇 마이크 녹음 141개를 지금 모델 `vica_bikaya_v1` 에 다시 넣음):

| 본인 목소리 | 녹음 | 지금 규칙(문턱 0.70 조각 2개 연속)으로 받음 | 한 조각 0.70 | 한 조각 0.40 |
|---|---|---|---|---|
| 쉬고 말함·부르기만 | 44 | 89 % | 91 % | 91 % |
| 바로 이어 말함 | 43 | 50 % | 63 % | 70 % |

- 같은 '비카야' 뒤에 말소리를 붙이는 것만으로는 83.5 → 78.5 % — 원인은 이어 말할 때의 '비카야' 발음이다(v1 은 말 끝 뒤
  약 0.4 s 무음까지 배웠다, 호출어 세션 분석).
- 관문을 풀 수는 없다: 11-17~18 놓침 14건은 귀로 들어 전부 '비카야 아님'이었고, "한 조각 0.9 이상이면 받기"면 7건이 헛호출이 된다.
- 호출이 확정된 뒤에는 지금도 이어진 말을 받는다(10-21~11-17 자유 창 423 중 0.4 s 안에 이어 말한 22건, 글자 대부분 온전).
  막히는 곳은 확정 판정 하나다.

## 2. 목표 · 하지 않는 것 · 실패로 보는 것

- 목표: 이어 말한 호출을 받는다. **최종 목표는 실제 동작**("비카야 화장실 가자"를 "네?" 없이 한 번에 처리) — 사용자 11-18.
- 헛호출을 늘리지 않는다.
- 하지 않는 것: 확정 관문(2조각 연속) 풀기, 긴급어 경로 변경, 호출 모델 학습(호출어 세션 몫).
- 실패로 보는 것: '기록만' 단계에서 로봇의 말·동작·반응 시간이 달라짐 · 마이크 처리가 멈춤 · "멈춰"가 늦어짐.

## 3. 접근

| 방법 | 장점 | 한계 | 결정 |
|---|---|---|---|
| 관문 풀기(한 조각이면 받기) | 가장 간단 | 헛호출 급증(놓침 14건 중 7건) | 버림 |
| 재학습만(v2) | 호출 판정 자체가 나아짐 | 얼마나 오를지 모름, 한 조각만 넘는 경우는 남음 | 호출어 세션이 진행 |
| **2단계: 한 조각 후보 → 말 끝까지 녹음 → 받아쓴 글자로 확정** | 지금 모델로도 50 → 63~70 %, 잡음은 글자 단계에서 걸러짐 | 30 % 는 후보도 안 됨(모델이 못 들음) | **채택 — v2 와 함께 쓴다** |

**단계(사용자 11-18):** 먼저 **기록만**, 숫자를 본 뒤 **실제 동작**으로 바꾼다. 처음부터 바꿀 수 있게 스위치 하나로 만든다.

## 4. 설계 — 기록만 (`VICA_WAKE_CAND=log`)

- 스위치 `.env` `VICA_WAKE_CAND=off|log|on`, 기본 `off`. `on`(실제 동작)은 이 설계에서 만들지 않는다 — 값이 `on` 이어도
  `log` 로 돌고 경고 한 줄을 남긴다. 후보 기준 `VICA_WAKE_CAND_MIN`(기본 0.40).
- 후보: 쉬는 상태(idle)에서 호출 점수 덩어리가 **확정 없이 끝났고** 최고점이 기준 이상인 것. 로봇 자기 말(self)은 뺀다.
- 후보가 되면 `wakeword_monitor` 가 **조용히** 소리를 모은다: 직전 2.5 s 링(여기에 '비카야'가 들어 있다) + 뒤따르는 말이
  끝날 때까지(칩 VAD, 말 시작 기다림 0.5 s, 상한 8 s). 호출 발행·"네?"·듣기 창·미션 판정은 없다.
- 모으는 동안에도 호출 확정·긴급어 판정은 평소대로 돈다. 확정이 나면 모으던 것은 버리고 평소 흐름을 탄다.
- **받아쓰기는 그 자리에서 하지 않는다.** 소리와 점수만 저장하고, 글자·통과 판정은 오프라인 도구가 로봇이 쉴 때 한다
  — 마이크 스레드와 대화 받아쓰기가 지연되지 않게(실패 조건).
- 저장: `~/vica_data/wake_clips/` 의 `clips.jsonl` 에 줄을 더한다(기존 칸 유지). 새 칸: `frames_over`(문턱 넘은 조각 수) ·
  `longest_run`(가장 긴 연속) · `model`(모델 파일 이름) · `cand`(후보 여부) · `utter_file`(링 + 뒤따른 말 wav) · `utter_sec`.
  확정 호출(wake)도 `frames_over`·`longest_run`·`model` 을 남긴다.
- 호출 모델 바꾸기는 지금 있는 `VICA_WAKE_MODEL_A` 로 한다(v2 가 오면 파일만 지정).

## 5. 시험 기록과 점검 페이지

- 오프라인 도구(로봇이 쉴 때): 후보·확정 사건마다 받아쓰기 → **글자 통과** = 첫 낱말이 "비카야"와 한 글자 이내로 다르거나
  "카야"로 끝나는 2~4자, 또는 "비카"(근거: 듣기 창 말소리 1,100건 중 이 꼴 38건, 모두 실제 호출로 보임). 다른 모델로 조각
  점수를 다시 재는 것도 여기서 한다(v1·v2 비교).
- 사건마다 남는 것: 시각 · 모델 · 최고점 · 넘은 조각 수 · 연속 수 · **지금 규칙 통과** · 받아쓴 글자 · **2단계 통과** · 소리.
- 점검 페이지: 사건마다 소리를 듣고 "비카야 맞음 · 바로 말 / 맞음 · 부르기만 / 아님 / 모르겠음"을 표시한다(11-18 페이지
  `~/vica_data/wake_near_review_20261118/wake_near_site.py` 를 넓힌다). 위에 요약표 — 지금 규칙·2단계 각각
  **맞게 받음 · 헛호출 · 놓침**.
- 합격(실제 동작으로 넘어가는 기준, 숫자는 첫 기록을 보고 사용자와 정한다): 이어 말한 진짜 호출의 받는 비율이 오르고,
  사람이 '아님'이라 한 사건의 2단계 통과가 0건.

## 6. 실제 동작(`on`)으로 바꿀 때 — 다음 설계에서 정할 것

- 2단계 통과 시: 호출 발행에 "말이 붙어 있음" 표시 → 미션은 "네?"를 생략하고 판정(대답할 상태인가)만 한다
  (`on_wake_call` — 지금은 무조건 하던 말을 끊고 "네?"). 판정이 나면 호출어 노드가 쥐고 있던 글자('비카야'를 뗀 뒷말)를
  평소 발화처럼 내보낸다(지금의 판정 대기·쥔 말 `_held` 장치).
- 받아쓰기를 그 자리에서 해야 하므로 지연·GPU 겹침을 잰다. 확인음(짧은 소리)을 낼지는 승인 사항.
- '비카야'만 부르고 쉬는 경우는 지금 흐름(2조각 확정 → "네?") 그대로다.

## 7. 빌더에게 맡기는 것

- 모으기 상태의 이름과 `wakeword_monitor` 안 배치, 상한·기다림의 환경변수 이름.
- 오프라인 도구와 페이지를 저장소 `tools/` 에 둘지 `~/vica_data` 에 둘지(다시 쓰는 것은 `tools/`).
- 시험: 모으기가 호출 확정·긴급어·듣기 창 판정을 바꾸지 않음을 기존 감시기 시험 방식(가짜 점수·가짜 VAD 주입)으로 고정.
