# 마이크 현장 점검기 설계 (mic_venue_check)

작성 2026-10-12 · 저장소 `vica-voice-llm` · 브랜치 `after_feedback_waiting`(지금 ⑫가 도는 브랜치, 새 브랜치 안 만듦)
상태: 사용자 검토 대기
화면 목업: https://claude.ai/artifact/2dZ8TTfMTNnLoDAv9Kom5Q (비공개, 가짜 데이터)

## 0. 배경

10-06 에 만든 자동 조정 도구(`tools/mic_venue_tune.py`, 설계 `2026-10-06-mic-venue-tune-design.md`)는 `feat/midm-fallback` 에만 있고
dev 에 들어가지 않았다. 그날 실기에서 세 가지가 드러났다.

- 잡음 측정이 불안정했다. 같은 복도에서 0.002·0.0043·0.009 가 나왔다(칩에 쓴 직후 잰 탓으로 추정, 미확인).
- 장소를 옮겨 다시 돌릴수록 에코 상한이 내려가는 구멍이 있었다.
- 소리가 매번 꽉 찼다(peak 1.0). 목소리 탓이 아니라 마이크 체인이 원래 크게 받는다(대화 2,523건 중 32 %가 peak ≥ 0.98).

그래서 사용자는 "시연장은 조정하지 않고 검증된 `.env` 값으로 고정"을 정했고(`VICA_AUDIO_PROFILE=off`), 다듬는다면
**값을 바꾸지 않고 확인만 하는 점검기**로 가자고 적어 두었다. 10-12 에는 시끄러운 환경에서 "멈춰"가 19번 중 10번만 걸린 것을
확인했는데, 10-06 도구는 "멈춰"를 아예 보지 않는다. 이 설계는 그 방향을 이어받는다.

## 1. 목적

시연장(10-27 전후)에 도착해 한 번 돌리면 "이 장소, 이 스피커 볼륨에서 비카가 제대로 듣는가"를 합격·주의·불합격으로 알려 준다.
기본은 확인만 한다. 사람이 결과를 보고 원하면 그 자리에서 값을 고쳐 다시 채점하고 `.env` 에 저장할 수 있다(사용자 요청 10-12).

사용자 결정(10-12):

| 결정 | 내용 |
|---|---|
| 목적 | 시연장 합격 판정기(A). 자동 조정은 살리지 않는다 |
| 시간 | 8~10분. "멈춰" 5번, "비카야" 쉬고 3번 + 이어서 2번, "그래"·"아니" 2번씩 (10-13 개정) |
| 말하는 사람 | 발표자 본인 목소리로만 시험한다 |
| 방법 | ⑫를 끄고 도구가 직접 듣는다 + 마지막에 ⑫로 실제 대화 한 번(사람이 확인) |
| 화면 | 휴대폰 웹 페이지. 실시간 소리·점수·잡음과 "지금 값으로 통과하는지"를 그래픽으로 |
| 값 고치기 | 사람이 고친다. 저장은 `.env` 에 직접, 백업과 되돌리기 포함 |
| 장비 | 마이크·스피커는 늘 같다. 볼륨 몇 번 눌렀는지 입력하는 단계는 없앤다 |
| 기준 숫자 | 초기값으로 두고 실제로 돌려 보며 다듬는다 |

## 2. 범위

하는 것:
- ⑫와 **같은 판정 코드**(`WakewordMonitor`)로 호출·청취 창·"멈춰"(한 조각 0.5 규칙과 small 확인 포함)를 판정한다.
- 실시간 표시, 단계별 녹음, 녹음 재채점, 합격 판정, 값 고치기, `.env` 저장·백업·되돌리기, 결과 기록.

하지 않는 것:
- 값 자동 추천·자동 조정(10-06 도구의 역할, 살리지 않음).
- Realtime·LLM·미션 자동 채점. 마지막 단계에서 사람이 ⑫로 대화 한 번 해 보고 확인한다.
  Realtime 은 청취 창이 잡은 소리를 그대로 받으므로, 청취 창 판정이 통과하면 마이크 쪽 책임은 끝난다.
- ROS 발행. 도구는 rclpy 를 쓰지 않는다. "멈춰"를 5번 말해도 진짜 비상정지가 걸리지 않는다.
- 관리자 앱 연동, 다른 사람 목소리 시험, 주행 중 실행.

## 4. 휴대폰 화면

목업(위 링크)과 같다. 영역은 다음과 같다.

- **A 상태 줄**: ⑫·⑬ 꺼짐, 칩 = `.env`, 연결됨. 하나라도 아니면 빨강이고 점검을 시작하지 않는다.
- **B 단계 카드**: 지금 할 말, 몇 번째인지, "녹음 시작" 버튼과 녹음 남은 시간.
- **C 소리 크기 막대**: 조각(0.08초) rms, 로그 눈금 0.001~1. 기준선 두 개(수음 최소·짧은 답 최소). 회색은 버림, 노랑은 긴 말만, 초록은 짧은 답도 받는 크기다.
  청취 창이 실제로 받아들이는지는 ⑫처럼 창 전체 클립의 rms 로 판정한다. 막대는 그 감을 보여 주는 용도다.
- **C 잡음 바닥**: 사람·로봇이 말하지 않는 동안(녹음 4초와 6단계 제외) 최근 10초 조각 rms 의 상위 10 %다. 막대와 그래프에 빗금으로 칠한다.
  옆 칩은 수음 최소까지 몇 배인지다. 2배 이상은 초록(10-06 규칙 "수음 최소 = 잡음 × 2"와 같은 여유), 1.3~2배는 노랑, 1.3배 아래는 빨강이다.
- **D 점수 막대**: "비카야"(문턱 0.70)와 "멈춰"(0.50, 로봇이 말하는 동안은 두 조각 연속 0.35 점선 추가). 가는 세로선은 최근 1.5초 최고값이다.
- **E 최근 10초 그래프**: 세 줄(소리·비카야·멈춰), 기준선 점선, 판정 순간 세로 표시, 6단계 구간 음영.
- **F 실시간 판정**: 실시간 감시가 낸 판정(호출 확정, "네" 받아들임, 멈춰 확정·기각·놓침과 이유). 결과표는 이것이 아니라 녹음 재채점으로 낸다(5절).
- **G 진행**: 항목별 점(통과·실패·남음)과 잡음 "점검 때 / 지금".
- **H~K 결과·값 고치기**: 종합 판정, 작은 실시간 막대, 결과표, 값 조절, 다시 채점·저장·원래대로.

갱신은 초당 12.5번(조각마다)이다. 여러 휴대폰이 동시에 열어도 같은 화면을 받는다.

## 5. 판정 방법

- **결과표는 녹음 재채점으로 낸다.** 단계마다 녹음을 남기고, 녹음 하나마다 새 `WakewordMonitor` 에 그대로 흘려 판정한다.
  처음 판정도, 값을 고친 뒤 다시 채점도 같은 방법이라, 같은 녹음과 같은 값이면 늘 같은 결과가 나온다.
- 모델(호출 점수, 대화 STT, 확인 STT)은 한 번 올려 나눠 쓴다. 재채점하는 동안에는 실시간 감시를 잠시 멈추고 화면에 "다시 채점 중"을 띄운다.
  같은 모델을 두 흐름이 동시에 쓰지 않게 하려는 것이다.
- 칩의 사람 말 표시(SPEECHDETECTED)는 녹음 때 조각마다 같이 기록하고, `WakewordMonitor.run()` 과 같은 규칙으로 재채점에 넣는다.
  청취 중일 때만 넣는다.
- 녹음 뒤에는 조용한 조각을 붙여 청취 창과 "멈춰" 확인이 닫힐 시간을 준다(10-06 `venue_replay` 의 방식).
- **받아쓰기 글자의 역할**: 처음에는 호출 문장의 "화장실"을 참고로만 보였다(운영에서는 Realtime 이 받아쓰기 전 소리를
  직접 듣는다). **10-13 개정**: 받아쓴 말에 "화장실"이 있어야 합격이다. 이어 말하면 듣기 창이 목적지 머리를 지난 뒤에
  열려 소리 자체에 "화장실"이 없다(Realtime 도 못 듣는다, 10-13 call_1 '로 가자') — 그것을 알 수 있는 것이 글자뿐이다.
  대가: whisper 가 "화장실"을 잘못 적으면 거짓 불합격이 날 수 있다.
  "그래"·"아니"는 ⑫도 받아쓰기로 긍정·부정을 가리므로 판정에 쓴다. 기준은 `normalize_short_reply` 결과가
  `AFFIRMATIVES`·`SOFT_AFFIRMATIVES`(긍정) 또는 `NEGATIVES`(부정)에 드는지다. 따로 만들지 않는다.
- "멈춰"는 ⑫와 같이 관문(한 조각 0.5 또는 두 조각 연속 0.5) → 확인 STT(small) → 정확 매칭(`match_emergency_transcript`)을 거쳐 확정된 것만 통과다.
  놓친 경우는 이유를 둘로 나눠 적는다. 점수가 낮았는지(관문 못 넘음), 점수는 넘었는데 확인 STT 에서 기각됐는지(받아쓴 글자를 함께 보임).

## 6. 합격 기준 (초기값)

숫자는 모두 초기값이다. `src/mic_check_rules.py` 한 곳에 모으고, 실제로 돌려 보며 다듬는다.

| 항목 | 합격 | 주의 | 불합격 |
|---|---|---|---|
| 잡음 바닥 | 수음 최소까지 2배 이상 | 1.3~2배, 또는 2단계 세 측정끼리 2배 넘게 차이 | 1.3배 아래 |
| "비카야" 쉬고 "화장실로 가자" ×3 | 3번 모두 호출 확정 + 청취 창이 받은 말에 "화장실"이 있음 | 다 통과했지만 가장 낮은 점수가 호출 문턱 + 0.1 아래 | 1번이라도 놓침 |
| "비카야화장실로가자" 이어서 ×2 (참고, 10-13) | 2번 모두 위와 같음 | 1번이라도 놓침 — 값으로 고칠 수 없는 귀의 한계라 불합격으로 치지 않고, 할 일은 "네?"를 듣고 말하기 | — |
| "그래" ×2, "아니" ×2 | 4번 모두 받아들여지고 긍정·부정이 맞음 | 다 통과했지만 가장 작은 클립 rms 가 짧은 답 최소의 1.5배 아래 | 1번이라도 못 받음 |
| "멈춰" ×5 | 5/5 확정 | 4/5 | 3 이하 |
| 로봇 혼자 말하기 | 자기 반응(호출·멈춰 확정) 0회 | 로봇 목소리 크기가 지난 점검의 1.5배 초과 | 자기 반응 1회 이상 |
| 오발동 | 3·4단계 녹음에서 멈춰 확정 0회, 5단계 녹음에서 호출 확정 0회 | | 1회 이상 |

- 6단계는 실시간으로 재므로 다시 채점할 수 없다. AGC·에코나 호출·멈춰 문턱이 6단계 때와 다르면 그 줄은 **다시 녹음**이다.

- 로봇 목소리 크기는 6단계 재생 중 조각 rms 의 평균이다(에코 지우기를 거친 뒤 소리). "지난 점검"은 `~/vica_data/mic_checks/` 의
  가장 최근 결과다. 처음 돌릴 때는 숫자만 보인다. 시연 전에 연구실에서 한 번 돌려 두면 그 값이 기준이 된다.
- 종합: 모두 합격이면 **시연 가능**, 주의가 있으면 **시연 가능 · 확인 필요**, 다시 녹음할 단계가 있으면 **다시 녹음 필요**,
  불합격이 있으면 **고친 뒤 다시**. 가장 나쁜 항목을 따른다(불합격 > 다시 녹음 > 주의 > 합격).

불합격일 때 화면에 띄우는 할 일:

| 상황 | 할 일 |
|---|---|
| 잡음 빨강 | 에어컨·환풍기 같은 소음원을 찾거나 로봇 자리를 옮긴다. 또는 수음 최소를 올린다 |
| 호출 놓침 | 손잡이 쪽을 향해 또렷하게 다시 해 본다. 그래도 놓치면 호출 문턱을 본다 |
| "그래"·"아니" 못 받음 | 클립이 작았으면 짧은 답 최소를 낮춘다 |
| "멈춰" 놓침, 점수 낮음 | 잡음을 확인한다. 멈춰 문턱을 낮출 수 있지만 오발동이 늘어난다는 경고를 함께 띄운다 |
| "멈춰" 놓침, 확인 STT 기각 | 받아쓴 글자를 보여 준다(예: "멈추라"). 말투 문제인지 판단하는 데 쓴다 |
| 자기 반응 | 스피커 볼륨을 낮추고 6단계만 다시 한다(10-06 저녁 실패 원인) |

## 7. 값 고치기

| 값 | 지금(`.env`·코드) | 허용 범위 | `.env` 줄 | 바꾼 뒤 |
|---|---|---|---|---|
| 수음 최소 | 0.008 (코드 상수) | 0.005 ~ 0.015, 0.0005 단위 | `VICA_LISTEN_MIN_RMS` (새 줄) | 다시 채점 |
| 짧은 답 최소 | 0.020 (코드 상수) | 0.012 ~ 0.025, 0.001 단위 | `VICA_SHORT_ANSWER_MIN_RMS` (새 줄) | 다시 채점 |
| 호출 문턱 | 0.70 | 0.50 ~ 0.90, 0.01 단위 | `VICA_WAKE_THRESHOLD` | 다시 채점 |
| "멈춰" 한 조각 문턱 | 0.50 | 0.40 ~ 0.70, 0.01 단위 | `VICA_EMERGENCY_SINGLE_FRAME` | 다시 채점 |
| AGC 목표 | 0.007 | 0.005 · 0.007 · 0.010 (써 본 값만) | `VICA_MIC_AGC_DESIRED` | 2~6단계 다시 녹음 |
| 에코 지우기 | 센(1.5·켜짐) | 센(1.5·켜짐) · 중간(1.0·켜짐) · 공장값(1.0·꺼짐) | `VICA_MIC_GAMMA_ETAIL`, `VICA_MIC_NLATTEN` | 6단계 다시 |

- 허용 범위는 10-06 설계의 실측 근거 범위를 따른다. 호출 문턱은 지금 0.70(10-08 결정)을 가운데로, "멈춰"는 놓침 기록 바닥(0.3)보다 위인 0.40을 하한으로 둔다.
  `.env` 의 지금 값이 목록에 없으면 그 값도 선택지로 함께 보인다.
- 검사: 짧은 답 최소가 수음 최소의 1.5배보다 작으면 저장하지 않는다(10-06 규칙). "멈춰" 문턱이 0.50 아래면 경고를 띄운다.
- 값을 움직이면 실시간 감시의 문턱이 바로 바뀌고 화면 기준선이 따라 움직인다. AGC·에코는 칩에 바로 쓴다(점검 중에만).
- **다시 채점**: 남긴 녹음을 새 값으로 재채점하고, 결과표에 처음과 달라진 줄 아래 "처음 값"을 함께 보인다. AGC·에코가 바뀌었으면
  해당 단계를 "다시 녹음"으로 표시한다(칩이 소리 자체를 바꾸므로 녹음이 무효다).
- **저장**: `.env` 에 쓸 줄을 먼저 보여 주고 "확인하고 저장"을 눌러야 쓴다.
  1. 지금 `.env` 를 `~/vica_data/mic_checks/env_backups/.env.<YYYYMMDD-HHMMSS>` 로 복사한다.
  2. 키가 있으면 그 줄을 바꾸고, 없으면 끝에 `# 마이크 점검기에서 추가` 머리 아래 붙인다.
  3. 바꾼 줄 끝에 `  # MM-DD <장소> 점검에서 바꿈 (전 <옛 값>)` 를 남긴다.
  4. 같은 키가 주석 아닌 줄로 두 번 이상 있으면 쓰지 않고 알린다(어느 줄이 쓰일지 헷갈리지 않게).
  5. 관계없는 줄과 주석, 줄 순서는 그대로 둔다.
  화면에 "⑫를 다시 켜야 적용됩니다"를 띄운다.
- **원래대로**: 마이크 값 7개(`env_file.KEYS`)만 가장 최근 백업의 값으로 되돌린다. 나머지 줄(지도·목적지 등)은 지금 그대로 둔다. 백업에 있던 키는 그 값으로 쓰고(`# MM-DD 원래대로 (백업 <파일>)` 표시), 백업에 없던 키는 줄을 지워 기본값으로 돌린다. 되돌리기 전 지금 `.env` 전체는 `.env.<시각>.before-restore` 로 남긴다.
  휴대폰 버튼(확인 한 번)과 명령줄(`--restore`, 터미널에서 y/n) 둘 다 있다.
- **끝낼 때**: 정상 종료든 Ctrl+C 든 칩을 `.env` 값으로 되돌린다(저장했다면 새 값). 도구가 칩에 써 본 값이 ⑫ 밖에 남지 않게 한다.

## 8. 기록

`~/vica_data/mic_checks/<YYYYMMDD-HHMM>_<장소>/`

- `result.json`: 점검 때 값, 측정치(잡음 세 번, 클립 rms, 점수, 확인 STT 글자·시간, 로봇 목소리 크기), 항목별 판정, 종합, 재채점 이력, 저장 여부

여러 번 돌린 결과를 나란히 놓고 6절 기준을 다듬는 데 쓴다. 녹음은 이 폴더에만 남고 밖으로 보내지 않는다.

## 9. 코드 구조

중계 비유: 마이크 → **판정실**(`WakewordMonitor`, ⑫와 같은 코드) → **중계차**(웹 서버) → **휴대폰**. 버튼은 반대로 흐른다.

| 파일 | 새로·수정 | 하는 일 |
|---|---|---|
| `src/wakeword_monitor.py` | 수정 | ① `listen_min_rms`, `short_answer_min_rms` 생성자 인자. 기본값은 `VICA_LISTEN_MIN_RMS`, `VICA_SHORT_ANSWER_MIN_RMS`, 없거나 잘못된 값이면 지금 상수(0.008, 0.02). `_listen_step` 이 모듈 상수 대신 이 값을 쓴다 ② `set_thresholds()` 로 실행 중 문턱(호출·멈춰 한 조각·두 문턱)을 바꾼다 ③ 선택 콜백 `on_frame(info)`: 조각마다 rms·호출 점수·멈춰 점수·상태. 안 주면 하는 일이 없다 |
| `src/ros_wakeword_node.py` | 수정 | 시작 로그에 수음 최소·짧은 답 최소를 더한다. 새 `.env` 줄이 없으면 동작은 지금과 같다 |
| `src/mic_check_rules.py` | 새로 | 합격 기준 초기값(한 곳)과 판정 함수. 순수 함수 |
| `src/mic_check_replay.py` | 새로 | 녹음 재채점. 10-06 `venue_replay.py` 를 지금 귀 코드(대화 STT·확인 STT 분리, 한 조각 규칙)에 맞게 옮기고 "멈춰" 확인을 더한다 |
| `src/env_file.py` | 새로 | `.env` 읽기·바꾸기·백업·되돌리기, 범위·1.5배·중복 키 검사 |
| `tools/mic_venue_check.py` | 새로 | 진입점. 시작하자마자 ⑫처럼 `.env` 를 읽는다(문턱 기본값이 `.env` 에서 오므로). ⑫·⑬ 확인(`/proc` 명령줄, 자기 자신 제외, ⑫ 중복 검사와 같은 무늬 `vica_voice.launch.py`·`-m src.ros_`), 모델 적재, 마이크 스트림, 칩 읽기·쓰기·확인, 단계 진행, 6단계 재생, 기록, 끝낼 때 칩 복귀. 마이크 찾기·칩 쓰기·녹음·재생은 10-06 도구에서 옮긴다 |
| `tools/mic_check_web.py` | 새로 | websockets 15 하나로 `/` 는 페이지, `/ws` 는 실시간 통로(`process_request`). 기본 포트 8770(`--port`), 같은 와이파이에서 연다 |
| `tools/mic_check_page.html` | 새로 | 휴대폰 화면. 목업을 실제 데이터로 |
| `.env.example` | 수정 | 새 두 줄 설명 |
| `docs/mic-venue-check.md` | 새로 | 사용법(시연장 순서, 결과 읽기, 되돌리기) |

- 진행 로직은 `src/mic_check_session.py` 로 나눴다(하드웨어 없이 시험하려고). 단계별로 녹음할 때의 칩 값을 따로 기억해,
  AGC 를 바꾼 뒤 그 단계를 녹음하면 그 단계는 처음부터 다시 녹음한다.

실행 구조: 마이크 콜백 → 조각 큐 → 처리 스레드(`process_frame`, 녹음, 잡음 통계) → 웹 스레드(asyncio)로 조각 정보 전달.
휴대폰 명령(녹음 시작, 이 단계 다시, 값 바꾸기, 다시 채점, 저장, 원래대로)은 명령 큐로 처리 스레드에 넘긴다.
새 의존성은 없다(`websockets` 15.0.1 이미 설치).

## 10. 시험과 완료 기준

단위 시험:

- `test_wakeword_thresholds.py`: 새 인자가 청취 판정에 실제로 쓰임, 인자·`.env` 없으면 지금과 같음, 잘못된 `.env` 값은 기본값, `set_thresholds` 반영, `on_frame` 이 없을 때와 판정이 같음
- `test_mic_check_replay.py`: 가짜 모델로 호출 확정·"네" 받아들임·"멈춰" 확정·확인 STT 기각·관문 못 넘음 구분
- 기존 시험(902개) 모두 통과

실기(연구실, ⑫ 끈 상태, 로봇 정지):
1. 휴대폰으로 접속해 막대·잡음·그래프가 움직인다.
2. 1~7단계를 마치고 결과표가 나온다. 소요 8~10분.
3. 값 하나를 바꿔 다시 채점하고, 저장한 뒤 `.env` 차이와 백업을 확인한다.
4. ⑫를 다시 켜 시작 로그에 새 값이 보이고, 평소 대화 5턴이 정상이다.
5. "원래대로"로 되돌리고 ⑫ 시작 로그가 원래 값이다.
6. 이때 잰 로봇 목소리 크기가 이후 점검의 비교 기준이 된다.

## 11. 알려진 한계

- 발표자 한 사람 목소리로만 시험한다. 심사위원·관객이 직접 말하면 작은 목소리 여유는 따로 보지 않는다(사용자 결정).
- 6절의 숫자는 초기값이다. 맞는 값은 실제로 돌려 봐야 안다(사용자 10-12).
- 녹음 재채점과 실시간 판정은 같은 코드지만 흐름이 달라(앞뒤 소리 유무) 드물게 다를 수 있다. 결과표는 재채점만 쓴다.
- 30초 로봇 혼자 말하기로 자기 반응 0회를 봤어도, 더 긴 실제 운영에서 반응이 없다는 보장은 아니다.
- 저장한 값은 ⑫를 다시 켜야 적용된다. 시연 뒤 되돌리는 것을 잊으면 시연장 값이 계속 쓰인다. 바꾼 줄 표시와 ⑫ 시작 로그로 알아챈다.
- 10-06 의 잡음 불안정 원인은 아직 모른다. 이번에는 2단계 세 측정의 차이와 실시간 잡음 흐름으로 드러나게만 한다.

## 12. 10-06 도구와의 관계

`feat/midm-fallback` 은 건드리지 않는다. 마이크 찾기, 칩 쓰기·확인, 녹음, 멘트 재생, `venue_replay` 의 재채점 방식만 이 브랜치로 옮겨
지금 귀 코드에 맞게 고친다. 장소 프로필(`audio_profile.py`, `current.yaml`)과 자동 계산 규칙(`mic_rules.py`)은 옮기지 않는다.
`.env` 의 `VICA_AUDIO_PROFILE=off` 줄은 이 브랜치에서 읽는 곳이 없으니 그대로 둔다.
