## 4. 방식 비교

| | 가. 칸만 늘리기 | 나. LLM 이 도구를 부르고 대화도 이끎 | 다. LLM 은 도구만 부름(선택) |
|---|---|---|---|
| 방식 | `reserve` 의도와 시설·날짜·시각·이름 칸을 `_IntentDraft` 에 추가 | 도구를 주고 이름 묻기·되읽기·완료 문장도 LLM 이 지음 | 도구 호출은 LLM, 묻는 문장·확인·저장은 코드와 미션 |
| 도구 호출인가 | 아님 | 맞음 | 맞음 |
| 되읽은 내용 = 저장 내용 | 보장 | 보장 안 됨 | 보장 |
| 도구 추가 | 칸이 계속 늘어남 | 도구만 추가 | 도구만 추가 |

'다'를 고른 근거(11-18 측정, 같은 발화 32개, 도구 3개 중 하나를 항상 부르게 한 조건):

| 모델 | 예약 12: 값까지 맞음 | 그 밖 13 | 이름 대답 2 | 전체 32 | 평균 응답 |
|---|---|---|---|---|---|
| gpt-5.4-mini | 12 | 13 | 2 | 32 | 1.0 s |
| Realtime(글자 입력) | 12 | 12 | 2 | 31 | 0.9 s |
| 로컬 midm2-mini | 3(말하지 않은 값을 버리면 12) | 9 | 0 | 16 | 1.6 s |

- 로컬의 실패 세 가지가 모두 LLM 에 대화를 맡길 때 생기는 것이다: 말하지 않은 값을 지어냄 · 이름 대답에 도구를 다시
  부르지 않고 완료를 말함 · 업무 도구만 주면 이동 요청에 없는 도구(`go_to`)를 지어내거나 예약을 부름.
- 업무 도구만 주고 고르게 둔 조건은 로컬 13행 중 6행만 맞았고, `set_intent` 를 같이 준 조건은 10행이 맞았다. 그래서 모든
  말을 도구 호출로 받는다(5.1).
- 한계: 측정용 짧은 지시문, 대화 기록 없음, 지은 문장, 한 번씩, Realtime 은 글자 입력. 운영 조건은 7절에서 다시 잰다.

## 5. 구조

```
받아쓴 글자·소리
  → 긴급어·멈춤 말(지금 그대로, LLM 이전)
  → 예약 진행 상태가 열려 있으면 그 단계의 규칙(5.3)            ← 새로
  → 글자 규칙(지금 그대로)
  → LLM: 도구 하나 호출 — set_intent | reserve_facility          ← 출력 형식이 바뀜(5.1)
       set_intent       → 지금의 VicaIntent 흐름 그대로
       reserve_facility → 예약 진행 상태(5.2·5.3)
  → VicaIntent(ask_text·ask_kind) → 미션이 말함(지금 그대로)
예약 저장 → 예약 파일(5.4) → /vica/reservation/event → 앱 팝업·목록(5.5)
```

### 5.1 LLM 출력: 모든 말을 도구 호출로

- 도구 두 개.
  - `set_intent`: 인자는 지금 `_IntentDraft` 의 칸 그대로(Realtime 은 지금처럼 `heard_text` 포함). 예약이 아닌 모든 말.
  - `reserve_facility`: `facility`(시설 목록의 이름) · `date`(사용자가 말한 표현 그대로) · `start_time`·`end_time`(24시간 HH:MM,
    `end_time` 은 끝 시각을 말했을 때만) · `name`(말했을 때만). 필수 인자는 없다. 설명에 "실제 예약은 사용자 확인 뒤 시스템이
    한다"를 적는다. Realtime 에서는 `set_intent` 처럼 `heard_text`(들린 말 그대로)를 함께 받는다 — 5.2 의 값 거르기가 이 글자를 쓴다.
- 저장(commit)은 도구로 주지 않는다. LLM 이 부를 수 있는 것은 예약 '요청'까지다.
- 경로별 구현
  - gpt-5.4-mini: `ChatOpenAI.bind_tools([...], tool_choice="required")`. 측정에 쓴 방식(`measure_cloud.py`).
  - Realtime: 세션 `tools` 에 두 도구, `tool_choice` 를 `set_intent` 강제에서 `"required"` 로.
  - 로컬 midm2-mini: 지시문 앞에 모델이 학습한 도구 문구(GGUF 내장 틀의 문장, `measure.py` 의 `TOOL_RULES`)와
    `tool_list:` JSON 을 넣고, 출력의 `<tool_call>{"name":…,"arguments":…}</tool_call>` 을 코드가 읽는다. Modelfile 과
    `OLLAMA_GO_TEMPLATE=1` 은 그대로. KT 기본 시스템 문구는 붙이지 않는다(측정: 붙이면 13행 중 2행).
- 도구 호출이 없거나, 목록에 없는 도구 이름이거나, 인자가 JSON 이 아니면 지금의 실패 처리(`LLM_UNAVAILABLE` 갈래)와 같은
  길로 보낸다. 다만 로컬에서 도구 없이 글만 온 경우는 `set_intent(question, reply=글)` 로 받는다(측정: "너 이름이 뭐야?").
  예외: 예약 진행 상태가 열려 있거나 발화에 예약 낱말이 있으면 그 글은 버리고 ⑨를 말한다. 측정에서 그 글이 "… 예약해
  드렸습니다"였다. 저장 없는 완료 문장이 음성으로 나가면 안 된다.
- 경로마다 `.env` 로 끄고 켠다(기본 꺼짐). 꺼진 경로는 지금 코드 그대로 돈다. 예약 낱말이 든 말이 꺼진 경로로 오면
  문장 ⑨를 말한다.

### 5.2 `reserve_facility` 를 받았을 때 (코드)

아래에서 '글자'는 글자 경로에서는 받아쓴 글자, Realtime 에서는 `heard_text` 다.

1. 시작 조건(P2): 미션이 쉬는 상태이고, 열린 질문이 없거나 kind `open` 인 질문("네?", "어디로 가고 싶으신가요?", ③)일 때만
   받는다. 그 밖(안내 주행 · 일시정지 · `confirm`·`yesno`·`choice`·`minutes` 질문이 열림)은 ⑨, 끝. 순찰 중과 사람 접근
   질문 중(`awaiting_user`)에는 아무 말도 하지 않는다 — 미션이 넘겨받은 문장을 버리는 상태다.
2. 값 거르기 — 글자에 없는 값은 버린다.
   - `name`: 글자에 그 이름이 없으면 버린다.
   - `facility`: 글자에 시설 이름이나 별칭이 없으면 버린다.
   - `date`·`start_time`: 코드가 글자에서 날짜·시각 표현을 읽는다(오늘·내일·모레·요일·"N월 N일", "오전/오후 N시 (반|N분)").
     읽었으면 그 값을 쓴다. 못 읽었고 글자에 날짜·시각 낱말이 있으면 LLM 값을 쓴다. 낱말이 없으면 버린다.
   - LLM 값과 코드가 읽은 값이 다르면 로그에 남긴다.
3. 모자란 값을 차례로 묻는다: 시설 → ⑦, 날짜나 시각 → ⑤.
4. 끝 시각: 글자에 끝 시각("…부터 세 시까지")이 있으면 그 값(P9), 없으면 시작 + 시설의 기본 시간(D3). 끝이 시작보다
   이르거나, 지난 시각이거나, 운영 시간을 벗어나면 ⑧. "한 시간만" 같은 길이 표현은 이번에 읽지 않는다 — 기본 시간으로
   되읽게 되고 사용자가 ②에서 거절할 수 있다.
5. 같은 시설에 겹치는 예약이 있으면 ④.
6. 이름이 없으면 ①, 있으면 ②(확인 질문).

### 5.3 예약 진행 상태 (음성 노드, 한 번에 하나)

- 쥐는 것: 시설 · 날짜 · 시작 · 끝 · 이름 · 지금 단계 · 넘긴 질문 문장.
- 질문을 넘긴 뒤의 대답은, 질문 기록(`/vica/question`)의 열린 질문 문장이 내가 넘긴 문장과 같을 때만 이 상태의 대답으로
  본다("다시 출발할까요?"를 `RESUME_CONFIRM` 문장으로 알아보는 지금 방식과 같다).
- 단계별 처리
  - 이름을 기다림(①): 받아쓴 글자에서 끝말("입니다"·"이에요"·"예요"·"요" 등)을 떼고 한글 2~5자면 이름으로 쓴다(P4).
    부정·취소 말이면 ⑥. 그 밖은 일반 해석으로 보내고 진행 상태를 버린다.
  - 값을 기다림(⑤·⑦·④·⑧ 뒤): 일반 해석으로 보낸다. `reserve_facility` 가 오면 5.2 로 이어 가되 이미 쥔 값은 유지한다.
  - 확인을 기다림(②): 지금 글자 규칙의 승낙이면 저장(5.4) → 알림(5.5) → ③. 거절이면 ⑥. `reserve_facility` 가 오면
    새 값으로 고쳐 ②를 다시 묻는다. 그 밖은 일반 해석으로 보내고 진행 상태를 버린다.
- 버리는 때: 저장함 · 거절 · 다른 명령 · 질문이 대답 없이 닫힘 · 대화 맥락이 비워짐(`_history.begin_turn`).
- 대답을 기다리는 문장(①②③④⑤⑦⑧)은 `VicaIntent.ask_text`·`ask_kind` 로 넘겨 미션이 말한다(`one_voice.held_resume_carrier`
  와 같은 꼴: intent `clarify`, `reply` 빈 값). `ask_kind` 는 ② `yesno`, 나머지 `open`. 쉬는 상태에서 이 꼴이 말해지는 것은
  코드로 확인했다(`mission_logic._say_handed_question`).
- 대답을 기다리지 않는 안내(⑥·⑨)는 음성 노드가 말한다(P8): intent `question`, `reply` 에 문장. 미션은 의도를 받으면 열린
  질문을 닫고(`question_record` 의 `answer`) 따로 말하지 않는다. `one_voice.voice_may_speak` 는 질문이 열린 동안에도
  `question` 의 답을 허용한다.
- 예약 흐름이 만든 의도는 `ros_node._publish_intent` 의 재청취 기각(`is_relisten_noise`)과 로컬 규칙의 대꾸 바꾸기를 거치지
  않게 한다. `reply` 가 빈 `clarify` 는 질문 뒤 문맥 창 안에서 그 기각에 걸려 버려진다(빌더 검토에서 확인).
- 소리 모드(P7): 예약 질문(①·②)이 열려 있으면 소리 경로는 그 발화를 처리하지 않고, 받아쓴 글자(`/vica/user_text`)가 오면
  위 단계 규칙으로 처리한다(`ros_node` 의 "소리 경로 결과 없음 — 텍스트 경로가 처리" 길). 규칙이 일반 해석으로 넘기는 말은
  글자 경로 LLM 이 읽는다. 첫 요청과 값을 기다리는 단계(④⑤⑦⑧ 뒤)는 지금처럼 소리 경로가 읽는다.
- 질문이 닫히는 경우는 대답 말고 세 가지다: 듣기가 빈손으로 끝남 · 미션 상태 변화 · "비카야" 재호출("네?"가 새 질문이 됨).
  세 경우 모두 진행 상태를 말없이 버린다. 되묻기(11-14 설계 4.5)가 들어오면 그때 이어 가게 한다.
- 저장에 실패하면(파일 쓰기 오류) ③ 대신 ⑨를 말하고 진행 상태를 버린다. 저장되지 않은 예약을 완료라고 말하지 않는다.

### 5.4 저장

- 폴더 `~/vica_data/reservations/`(`.env` 로 바꿀 수 있게).
  - `facilities.yaml`: 시설마다 이름 · 별칭 · 기본 시간(시간) · 운영 시작·끝 시각. 시연용: 세미나실, 상담실.
  - `reservations.json`: 예약 배열. 한 건 = `id` · `facility` · `date`(YYYY-MM-DD) · `start`·`end`(HH:MM) · `name` ·
    `source`(`voice`) · `created_at`.
- 쓰기는 임시 파일에 쓴 뒤 이름 바꾸기. 쓰기 직전에 파일을 다시 읽어 겹침을 한 번 더 본다.
- 순수 모듈로 둔다(ROS 없이 시험): 읽기 · 겹침 판정 · 추가 · 취소.

### 5.5 앱 알림 · 목록 · 취소

- 알림: 음성 노드가 `/vica/reservation/event`(`std_msgs/String`, JSON)를 낸다(P1).
  `{"event": "reservation_created" | "reservation_canceled", "id", "facility", "date", "start", "end", "name", "source", "timestamp"}`
- 목록: `VICA_Supervisor/ros2/map_http_server.py` 에 `GET /reservations/list.json` 을 더한다(경비 기록 `/patrol/events.json`
  과 같은 방식, 읽기만). 앱은 화면을 열 때와 알림을 받을 때 다시 받는다.
- 취소: 앱이 `/vica/reservation/cancel_request`(`std_msgs/String`, 예약 id)를 내면 음성 노드가 파일에서 지우고
  `reservation_canceled` 를 낸다(P5). 앱은 그 알림을 받으면 목록에서 뺀다.
- 앱 화면: 보드 60(더보기 › 시설 예약, 날짜별 목록, 방금 등록 표시, ✕ 취소)·61(새 예약 팝업). 11-18 사용자 승인(D9).

## 6. 문장

미션이 말한다. ②만 값이 들어가는 틀이고 나머지는 고정 문장이다.

| # | 문장 | 언제 | 상태 |
|---|---|---|---|
| ① | 성함을 말씀해 주세요. | 이름이 없음 | 사용자 대본 |
| ② | {이름} 님 이름으로 {날짜} {시작}부터 {끝}까지 {시설} 예약할까요? | 값이 다 참 | 사용자 확정 |
| ③ | 네, 예약이 완료되었습니다. 이제 어디로 갈까요? | 저장 뒤 | 사용자 대본 |
| ④ | 그 시간에는 이미 예약이 있습니다. 다른 시간을 말씀해 주세요. | 겹침 | 사용자 확정 |
| ⑤ | 언제로 예약할까요? | 날짜나 시각이 없음 | 사용자 확정 |
| ⑥ | 예약하지 않았습니다. | 확인·이름 질문에 거절 | 사용자 확정 |
| ⑦ | 어디로 예약할까요? | 시설이 없음 | 사용자 확정(글자 고침) |
| ⑧ | 그 시간에는 예약할 수 없습니다. 다른 시간을 말씀해 주세요. | 지난 시각·운영 시간 밖 | 사용자 확정 |
| ⑨ | 지금은 예약을 받을 수 없습니다. | 쉬는 상태가 아님·경로가 꺼짐·저장 실패 | 사용자 확정 |

- ②의 날짜·시각은 말로 읽는다: 오늘·내일·모레는 그 말로, 그 밖은 "11월 20일". 시각은 "오후 두 시", "오후 한 시 반".
- 고정 문장은 미리 합성해 둔다(`src/mission_phrases.py` 방식). ②는 그때 합성한다.

## 7. 측정과 켜는 기준

- 경로별로 도구 출력을 켜기 전에 208행 재생(`tools/answer_replay.py`, 11-18 기준: 잘못된 행동 Mi:dm 17 · gpt 10~12 ·
  Realtime 11~13)을 도구 출력으로 다시 잰다. 기준보다 2 넘게 나빠지면 그 경로는 켜지 않는다(11-18: ±2 는 흔들림).
- 예약 묶음(11-18 의 32개에 끝 시각을 말한 발화 3개를 더하고 운영 지시문·대화 기록을 붙인 조건): 예약 발화가 5.2 를 거친 뒤
  값까지 모두 맞고, 그 밖 13개에서 `reserve_facility` 호출 0, 저장 없이 완료를 말하는 문장이 음성으로 나가는 경우 0.
- 순수 로직 시험: 값 거르기 · 날짜·시각 읽기 · 겹침 · 진행 상태 단계 · 문장 만들기 · 저장.
- 실기 장면(주행 없음): 대본 그대로 · 이미 예약 있음 · 확인에 "아니" · 이름을 잘못 들었을 때 "아니" · 이름 질문 중
  "화장실로 가자" · 날짜 없이 "세미나실 예약해 줘" · "두 시부터 세 시까지" · 이름 질문에 대답 없이 지나간 뒤 다시 요청.
  글자 모드와 소리 모드에서 각각 한다. 합격: 앱 목록·팝업이 저장과 같은 내용, 한 질문에 두 목소리 0, 저장 없는 완료 문장 0.
- Realtime 소리 입력에서 이름을 얼마나 듣는지는 실기에서 본다(11-18 측정에 없음). 틀려도 ②에서 걸린다.

## 8. 바뀌는 곳

- `vica-voice-llm`: 도구 정의와 세 경로의 출력 처리(`langchain_intent_parser.py`·`realtime_intent.py`) · 예약 진행 상태와
  규칙(새 순수 모듈) · 저장 모듈 · 날짜·시각 읽기 · 문장 · `ros_node.py` 배선(토픽 2개) · 미리 합성 문장 · `.env` 키 · 재생 도구.
- `VICA_Supervisor`: 화면 60·61 · `/vica/reservation/event` 구독 · 취소 요청 발행 · `ros2/map_http_server.py` 의 목록 응답.
- `vica_ros2_ws`: 없음. 넘겨받은 질문은 지금 `_say_handed_question` 이 말한다.
- 자료: `~/vica_data/reservations/facilities.yaml`(시연용 두 시설).

## 9. 순서 (각 단계 끝에 확인 가능)

1. 저장 · 날짜·시각 읽기 · 진행 상태 · 문장 — LLM 없이 시험으로 확인.
2. gpt-5.4-mini 도구 출력 + 재생 측정 → 켬 → 글자 경로로 대본 실기.
3. Realtime 도구 출력 + 재생 측정 → 켬 → 소리 경로로 대본 실기.
4. 앱 화면·알림·취소(목업 승인 뒤) + 지도 서버 목록.
5. 로컬 도구 출력 + 재생 측정 → 기준을 넘으면 켬.

## 10. 3-나-2 와의 관계

3-나-2(질문 kind 별 해석, `answer`·`question_id` 칸)는 LLM 출력 형식을 바꾼다. 이 설계가 그 출력을 도구 호출로 바꾸므로,
3-나-2 는 `set_intent` 의 인자에 칸을 더하는 일이 된다. 3-나-2 계획은 이 설계의 5.1 을 전제로 쓴다.

## 11. 빌더에게 맡기는 것

- `.env` 키 이름과 경로별 스위치 모양, 모듈·함수 이름.
- 날짜·시각 읽기가 덮을 표현의 범위(7절의 예약 묶음을 통과하는 선).
- 이름으로 보는 글자 조건의 세부(끝말 목록, 글자 수).
- '쉬는 상태'에 드는 `dialog_state` 값.
- 소리 모드에서 예약 질문이 열렸을 때 소리 경로를 비키게 하는 구현(5.3), 첫 요청을 소리·글자 두 경로가 둘 다 받을 때
  예약을 한 번만 처리하는 방법(지금 일시정지 중복 막기와 같은 자리).
- 토픽 QoS, 예약 id 모양, 앱 쪽 모델·화면 코드 구조.
