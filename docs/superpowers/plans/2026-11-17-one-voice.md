# 한 목소리 (설계 7절의 3-가) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 로봇이 사용자 대답을 기다리는 말은 모두 미션이 한다. 음성 노드는 질문 문장을 말하지 않고 `VicaIntent` 에 실어 미션에 넘긴다. 대답을 읽는 방법·되묻기 횟수·기다리는 시간은 바꾸지 않는다.

**Architecture:** 음성의 새 순수 모듈 `one_voice.py` 가 LLM·고정 문구의 질문을 `ask_text`·`ask_kind`·`ask_option_ids` 로 옮기고 `reply` 를 비운다. 목적지 제안(navigate + need_confirm)은 문장을 넘기지 않고, 미션이 목적지 `confirm_prompt` 로 직접 묻는다(결정 A). 미션은 넘겨받은 문장을 `_ask` 로 말해 2단계 질문 기록·듣기 요청이 그대로 따라 나온다. resume 보류·다시 묻기 판단은 음성에 남기고 말만 미션이 한다(결정 B).

**Tech Stack:** ROS 2 Humble(rclpy, rosidl), Python 3.10, pytest. 저장소 둘: `vica_ros2_ws`(`vica_interfaces`, `vica_mission_manager`), `vica-voice-llm`.

**Spec:** `docs/superpowers/specs/2026-11-14-question-aware-answers-design.md` — C2, 4.2(`ask_*` 칸), 4.4(한 목소리), C8, 7절 3-가. 근거 자료 `~/vica_data/voice_answer_audit_20261113/qa_all.csv`(질문 1,660건 중 `q_by=voice` 621건: 확인 질문 338 · LLM 되묻기 92 · 고르기 69 · 온보딩 68 · "네?" 54).

## Global Constraints

- **바뀌는 것은 누가 말하는지뿐이다.** `_IntentDraft`·LLM 지시문·Realtime `set_intent` 매개변수·글자 규칙은 손대지 않는다. 계획 끝에 `git diff <시작 커밋> -- src/langchain_intent_parser.py src/realtime_intent.py` 가 비어 있어야 한다.
- 결정 A(사용자 11-17): navigate 제안의 확인 질문은 미션 `_confirm_prompt_for(dest)` 문장이다. LLM 이 지은 확인 문장은 버린다.
- 결정 B(사용자 11-17): `should_forward_intent`·`reask_held_resume`·`should_reask_resume_on_silence` 는 그대로 둔다. "다시 출발할까요?"를 말하는 곳만 미션으로 옮긴다. 미션의 resume 확인 상태 이동(C8)은 3-나에서 한다.
- **결정 D(Claude 제안, 사용자 승인 11-17):** 미션이 지금 받지 않는 상태의 제안에는 확정 요청과 같은 거절 멘트를 한다. APPROACHING·SEEKING 은 `MSG_APPROACH_BUSY`, 관리자 주행은 `MSG_BUSY`, 도움 요청 `acknowledged` 는 `MSG_HELP_COMING`. 10-07 '제안 단계 침묵'의 이유("음성이 이미 물었다")가 없어지기 때문이다. 대기 장소로 가는 중(`_WAIT_MOVING_STATES`)·TURNING 은 지금처럼 말하지 않는다.
- `quiet_for_mission`·`identity_answer`·`spk_gate_question` 은 지우지 않는다(3-나에서 대답 처리와 함께 지운다).
- C5(사용자 질문에 LLM 이 답한 뒤 미션이 열린 질문을 곧바로 다시 들려주기·대답 대기 시계 멈춤)는 3-나에서 한다. 3-가에서는 지금처럼 미션의 15 s 다시 묻기가 그 일을 한다.
- 새 멘트·새 노드 없음. 긴급 경로(`emergency_filter`, `/vica/emergency`)는 손대지 않는다.
- 옛 설치본 호환: 음성은 `VicaIntent` 메시지에 `ask_text` 가 없으면 질문을 넘기지 않고 지금처럼 직접 말한다. 미션은 `getattr` 기본값으로 읽는다.
- 두 저장소 모두 `after_feedback_waiting` 에서 작업하고, 작업마다 커밋한다. 푸시·dev 머지는 하지 않는다. ROS 저장소에는 다른 작업의 미커밋 파일(`maps/`·`mdrobot_can_control*` 등)이 있으니 `git add` 는 파일 이름으로 지정한다.
- `colcon build`·유닛 재시작은 그때마다 사용자에게 묻는다. 자동 기동 유닛은 직접 `systemctl --user stop` 하지 않는다(모드 노드가 감시한다).
- rclpy 로거의 심각도를 조건식으로 고르지 않는다(2단계 검토 C1). 주석은 한국어로, 한 줄에 한 뜻.
- 질문 종류는 2단계와 같은 여섯 개다: `open`·`confirm`·`choice`·`yesno`·`yesno_inverted`·`minutes`.

## Review Focus

1. **옛 설치본 혼재**(음성만 새것, 또는 인터페이스를 빌드하기 전) — 질문이 사라지면 안 된다. 음성 `_hand_over` 가 꺼지면 지금처럼 말한다. Task 2 `test_supports_ask_fields_false_on_old_interface`, Task 6 `test_hand_over_is_skipped_without_ask_fields`.
2. **미션이 그 의도에 이미 말하는 상태**(접근 질문 다시 묻기·취소 확인 다시 묻기·도움 확인 다시 묻기) — 넘겨받은 질문은 버리고 한 번에 한 문장만 낸다. Task 4 `test_handed_question_dropped_when_mission_speaks`.
3. **고르기 후보 이름이 겹침** — "화장실"이 "남자 화장실" 속에 들어 있거나, 같은 이름이 둘("서울로봇고등학교" ×2)인 경우. Task 3 `test_choice_options_use_outer_names` · `test_choice_options_keep_same_name_twins`.
4. **일시정지 중 "다시 가자"** — 미션이 "다시 출발할까요?"를 묻는다. 침묵이면 한 번만 다시 묻고 멈춘 채 둔다. "네"면 다시 출발한다. Task 4 `test_held_resume_question_spoken_in_paused` · Task 6 배선 시험 · Task 7 실기 4번.
5. **질문이 열린 동안 사용자가 질문함**(`question`) — 음성이 답하고, 미션은 15 s 뒤 같은 질문을 다시 한다(지금과 같음). 그 밖의 음성 말(`LLM_UNAVAILABLE` 등)은 나가지 않는다. Task 3 `test_voice_may_speak_only_answers_while_question_open`.
