# 작업 로그 2026-07-22

## 요약

PC에서 STT-LLM-TTS를 가동하는 일이 없어지고 앞으로 Jetson 온디바이스에서만 운영하기로
확정함에 따라 저장소를 Jetson 전용으로 정리했다. LLM은 Ollama Cloud를 주 모델로 계속
사용하고, STT/TTS는 Jetson GPU에서 돈다.

## 결정 (사용자 확인)

- 로봇 없이 파이프라인만 돌리는 개발용 스텁: **완전 제거** (항상 실제 로봇/ROS2와 통합).
- 클라우드 LLM(Ollama Cloud): **주 모델로 유지** (기본값 그대로).
- FastAPI+SQLite 테스트용 목적지 백엔드: **제거, YAML 단일화**.

## 변경 내용

- 개발용 스텁 제거: `src/ros_robot_state_stub.py`, `src/ros_state_machine_stub.py`,
  `launch/vica_voice.launch.py`의 스텁 2개. CLI(`src/main.py`)는 유지하되 가짜
  로봇 상태 대신 `robot_state=None`(파서가 "위치 알 수 없음"으로 처리)을 쓴다.
  `/vica/robot_state` 발행과 state machine은 로봇 팀 노드(`ros2_ws`)가 담당한다.
- 테스트 백엔드 제거: `backend/`, `tests/test_backend.py`. `src/destination_loader.py`는
  `VICA_DEST_API`/httpx 경로를 없애고 `config/destinations.yaml`만 읽는다.
- Jetson 디바이스 기본값: `src/stt.py` 기본 `cuda`/`float16` + CUDA 실패 시 CPU 폴백.
  `src/tts.py`는 기존 GPU 우선/CPU 폴백 유지.
- 의존성 정리: `requirements.txt`에서 미사용 패키지 제거
  (`anthropic`, `openai`, `langchain-anthropic`, `langchain-google-genai`, `deepagents`,
  `kokoro-onnx`, `kokoro-tts`). LLM은 `langchain-ollama`만 사용.
- 문서 정합: `CLAUDE.md`(Phase 5 제거 표기), `docs/how-it-works.md`,
  `docs/ros2-interface.md`, `docs/jetson-setup.md`(LLM 클라우드 주 모델로 재정리),
  `.env.example`(클라우드 기본, 로컬은 선택, `OPENAI_API_KEY` 삭제).

## 검증

- `.venv`(Jetson, Python 3.10)에서 단위 테스트 통과: `test_destination`,
  `test_emergency`, `test_emergency_monitor` = **19 passed**. (`test_backend`는 제거)
- 변경 파일 `py_compile` 통과. 삭제한 스텁/백엔드/`VICA_DEST_API` 참조가 코드·살아있는
  문서에 남지 않음을 확인.
- 실제 마이크·스피커·Ollama Cloud 호출·ROS2 노드 실행은 자동화하지 않음(Testing Rules).

## 남은 항목 (follow-up)

- `requirements.txt`는 PC(Python 3.11+) freeze라 일부 핀(예: `numpy==2.4.6`)이 Jetson의
  Python 3.10에서 설치되지 않는다. Jetson 네이티브 재-freeze가 필요하다(별도 작업).
  `onnxruntime`은 Jetson에서 `onnxruntime-gpu`로 설치(`docs/jetson-setup.md`).
- 이 저장소는 아직 `main` 단일 브랜치다. 이번 작업은 `chore/jetson-only-cleanup`
  브랜치에서 진행했고 검토 후 병합 예정.
