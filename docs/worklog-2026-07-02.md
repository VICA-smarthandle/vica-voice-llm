## 지연 개선: intent 파싱 14~20초 → 3~4초
처음엔 긴 시스템 프롬프트의 prefill 이 병목이라고 추정했지만, **측정해보니 틀렸다.**
Ollama API 의 시간 분해(`prompt_eval_duration` / `eval_duration`)로 확인한 결과:

- prefill: 699 토큰을 1초 미만에 처리 (병목 아님, 반복 호출 시 KV 캐시로 0.1초)
- 진짜 원인: **gemma4:e2b 는 thinking 모델** — 답변 전에 보이지 않는 내부 추론
  텍스트를 길게 생성하며 매 호출 10~24초를 소비 (`think:false` 로 끄면 사라짐)

수정 (`src/langchain_intent_parser.py`, 커밋 `c77d619`):
- `reasoning=False` — intent 분류는 단순 작업이라 내부 추론 불필요. 품질 저하 없음
  (목적지 매칭, 간접 표현 "배고파"→식당, 멀티턴 확인 모두 정상 검증).
- `keep_alive=-1` — 모델 메모리 상주. 기본 5분 유휴 후 언로드되면 다음 발화가
  ~20초 콜드스타트가 되는 문제 방지.

교훈: **추측하지 말고 측정하라.** prefill 추정대로 프롬프트 축소부터 했다면 헛수고였다.

## 주요 발견 / 결정
- 모델 첫 호출은 로드 포함 ~20초, 로드 후 단문 응답은 1.6초 (35 tokens/s).
- `reasoning=False` 는 PC 클라우드 모델(gemma4:cloud)에도 적용됨 — PC 에서 동작 확인 필요.
- 오디오 장치는 HDMI/내장(APE)만 인식됨 — **USB 마이크/스피커 미연결**.
  STT/TTS 실기 테스트는 장치 연결 후 가능.
- onnxruntime 의 "GPU device discovery failed" 경고는 Jetson iGPU 를 데스크톱
  방식으로 못 찾는 것일 뿐, CPU 추론 정상 — 무시해도 됨.

## 실행법 (Jetson)
- CLI: `.venv/bin/python -m src.main` (마이크: `VICA_STT=1`)
- ROS2: `source /opt/ros/humble/setup.bash && source ros2_ws/install/setup.bash` 후
  `ros2 launch launch/vica_voice.launch.py`
